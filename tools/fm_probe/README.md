# Проверка нового FM на ESP32-S3 N16R8

Изолированный вычислительный стенд для десяти FM-машин из `4000b2e`. Генератор извлекает закреплённый исходный код во временный проект и меняет частоту ядра на **32 кГц**. Рабочая прошивка сохраняет восемь прежних FM-машин. Экран, SD, I2S и Teensy стенду не нужны.

Конфигурация: 16 MB flash, 8 MB **octal PSRAM**, `qio_opi`, 240 MHz; перед запуском проверяются размеры flash/PSRAM. WT32 N16R2 сохраняет `qio_qspi`.

## Подготовка и сборка

Из корня репозитория:

```sh
python3 tools/fm_probe/prepare.py
~/.platformio/penv/bin/pio run -d /private/tmp/dtrk-newfm-probe -e fm-probe
```

Требуются уже установленные PlatformIO и git-объект `4000b2ec2975f07e76c99aed7d83bb72630720f0`. Скрипт не обновляет ветки и не загружает прошивку. `--output` позволяет выбрать другую папку вне репозитория.

## Выбор устройства и прошивка

```sh
~/.platformio/penv/bin/python -m serial.tools.list_ports -v
```

Выбрать **только подключённую ESP32-S3** по USB VID/PID и расположению порта. Teensy (`16c0`) и остальные устройства для этого стенда не используются. Если текущая программа с TinyUSB не отвечает на автоматический вход в загрузчик, удерживать **BOOT**, нажать и отпустить **RESET**, затем отпустить **BOOT**. После этого повторно определить порт: ROM USB может получить другое имя.

Сначала проверить идентификатор чипа и flash, подставив найденный порт:

```sh
~/.platformio/penv/bin/python ~/.platformio/packages/tool-esptoolpy/esptool.py --chip esp32s3 --port /dev/cu.usbmodemXXX flash-id
~/.platformio/penv/bin/pio run -d /private/tmp/dtrk-newfm-probe -e fm-probe -t upload --upload-port /dev/cu.usbmodemXXX
~/.platformio/penv/bin/python ~/.platformio/packages/tool-esptoolpy/esptool.py --chip esp32s3 --port /dev/cu.usbmodemXXX --after watchdog-reset chip-id
~/.platformio/penv/bin/pio device monitor --port /dev/cu.usbmodemXXX --baud 115200
```

На проверенной плате обычный RTS-reset после загрузки оставлял ROM-загрузчик без вывода программы; watchdog-reset выше запускал программу. При необходимости нажать RESET уже после подключения монитора. Прогон заканчивается строкой `NEWFM DONE`; отсутствие этой строки означает неполный прогон. Текущая программа на выбранной ESP32-S3 заменяется стендом.

## Что измеряется

Для каждой машины: 1, 2, 4 и 8 голосов; обычные настройки, высокий тон/максимальный OVER и вариант с меняющимся TUNE. Один блок — 128 кадров, четыре обновления управления по 32 кадра. Время включает FM `trigger()`, `control()` и `render()`; в варианте с движением TUNE также пересчёт параметров. Голоса перезапускаются каждые 8 блоков (32 мс), DEC высокий, чтобы короткая SD VINTAGE не давала ложный выигрыш за счёт мёртвых интервалов. Дополнительно CHORD проверяется с TYPE16/BAL127/FENV127/WAVE96/OVER127 (восемь операторов) на низких/высоких нотах с фиксированным и меняющимся TUNE; TONE PNCH — на низких нотах. Строки CONFIG показывают фактические параметры и число операторов. В логе есть число активных голосов, среднее/пиковое время, доля от 4000 мкс и контрольная сумма, RMS и пик PCM; нечисловые значения считаются ошибкой.

Это **FM-ядро**, без трековых insert, мастер-эффектов, экранной нагрузки и I2S DMA. Для общего CPU нужно сопоставить результат с полным синтом (`esp32s3-headless`) и оставить резерв для управления/пиков; из одной средней нагрузки нельзя объявлять безопасный лимит полифонии. Звук новых машин на 32 кГц требует отдельной проверки. PSRAM N16R8 имеет другой интерфейс, чем N16R2; результаты стенда не доказывают отсутствие перегрузок на работающем WT32 с экраном.
