# Экспорт песни в WAV (мастер + стемы) — дизайн

Ветка `feature/teensy`. Принят 2026-10-15 со всеми рекомендациями (см. «Решения» в конце); план —
`2026-10-15-song-export.md`. Опирается на то, что уже есть:
- **Render WAV** (FILE → PROJECTS → Render WAV…, `src/ui/render_dialog.*`, `src/storage/render_io.*`,
  `src/teensy/render_server.cpp`, `lib/core/src/render.*`, `render_link.*`): офлайн-рендер на синт-плате,
  стерео 16 бит 44,1 кГц в `/samples/render/<проект>_P01.wav` / `_SONG.wav`, Tracks = ALL / SOLOED / STEMS.
  STEMS сейчас — **по проходу на дорожку**: дорожка соло, свои delay / reverb / компрессор, sidechain от
  других дорожек не действует; сумма стемов ≠ мастер.
- **Resample** (GRID → Resample track / pattern): тот же механизм с целью «банк» (моно, нормализация,
  обрезка тишины, без хвоста).
- Стриминг сэмплов (`2026-10-10-sample-streaming-design.md`), PSRAM только CS0, буфер PERF 6 с в PSRAM.

Иначе говоря, «экспорт» — не новая подсистема, а **расширение Render WAV**: один проход с отводами
(taps) по дорожкам и возвратам эффектов, несколько файлов за проход, петли паттерна, автохвост, 24 бит,
папка `/export`, скачивание по Wi-Fi.

## Цель

- Мастер стерео (как слышно, с компрессором, EQ, MAIN и soft clip) — песня или паттерн × N.
- Опционально стемы: каждая слышимая INT-дорожка в свой стерео-файл, плюс возвраты MOD / DLY / RVB
  отдельными стемами. Все файлы одной длины, начинаются с нуля — кладутся в DAW встык.
- Файлы на карте синт-платы в `/export/<проект>/…`, скачиваются с Wi-Fi-страницы.
- Прогресс, отмена; ошибки (`DISK FULL`, `WRITE FAILED`, `NO SYNTH`) — как у Render WAV.

## Что есть сейчас (выводы из кода)

- **Офлайн, не реальное время.** `RenderStart` паркует живой выход (`SynthStream::park(true)`: ISR
  отдаёт нули и выбрасывает очередь), сбрасывает синт; ESP гоняет свой `OfflineSequence` (секвенсор в
  PSRAM ESP, виртуальные блоки по 2902 мкс) и шлёт события кадрами `RenderBlocks` (до 8 блоков = 23 мс
  звука на кадр, stop-and-wait); Teensy рендерит их в `loop()` и пишет в `<path>.tmp`, на `RenderEnd`
  дописывает заголовок и переименовывает.
- **Стрим детерминирован.** На время рендера `stream::pool().sync = &stream::reader()`: недогруженный
  блок сэмпла читается с карты **синхронно**, рендер ждёт его. Поэтому «запись блокирует чтение на
  150–430 мс» для экспорта — вопрос скорости, а не щелчков: рендер просто стоит, пока карта занята.
  Два рендера одного спека побайтно равны (seed LFO при `reset()`, RNG секвенсора фиксирован).
- **Пул голосов.** Бюджет по цене (`setVoiceBudget`) действует и офлайн — детерминированно, рендер равен
  живому звуку. CPU-сторож (`setLoad`) офлайн формально не вызывается, но ISR в паркованном режиме
  всё равно зовёт `setLoad` с малой нагрузкой на тот же `Synth` (гонка, сейчас безвредная: после
  `reset()` пул полный, низкая нагрузка его не трогает). Отметить и закрыть флагом «parked → без setLoad».
- **Скорость** «примерно реальное время» (мануал): каждые 23 мс звука = рендер (на Teensy худший случай
  ≈65 % CPU реального времени) + RTT линка + запись 16 КБ. Лёгкие проекты должны идти быстрее; замера
  нет — первым шагом снять `speed = длительность / время` на 3–4 проектах.
- **Хвост.** `RenderDialog::kTailBlocks = 500` — это 1,45 с, а не «2 с» из комментария и мануала
  (2 с = 689 блоков). Исправить попутно.
- **Скачивание.** `storage::remoteFs()` — `fs::FS` поверх `FsRead` (480 Б за кадр, один запрос в полёте,
  упреждение 4 КБ). Веб-сервер ESP (`src/net/web.cpp`, синхронный `WebServer`) умеет только прошивки;
  «файлового менеджера на странице нет».

## Режим рендера

**Офлайн, выход заглушён** — как сейчас. Реальное время отклонено:
- запись 20 файлов параллельно со стримом в реальном времени даёт недогрузки (150–430 мс блокировки
  чтения при записи) — ровно то, от чего офлайн уже защищён синхронным чтением;
- офлайн быстрее на лёгких проектах и не ограничен CPU 80 % (сторож не нужен, блок может считаться
  дольше 2,9 мс);
- детерминизм нужен для нескольких проходов (ниже).

Единственный довод за реальное время — записать внешние MIDI-синты через LINE IN синхронно с
внутренним звуком. Это отдельная фича (вход в граф синта, запись с входа), не здесь.

## Стемы: что в них

Отводы в `Synth::renderCore`, только когда задан указатель `RenderTaps*` (живой путь не меняется,
проверяется тестом на побайтное равенство):

| Отвод | Где берётся | Что внутри |
|---|---|---|
| `T01..T16` | выход `runStrip` после `panAdd` (в `mixL_/R_` или в шину sidechain `scL_/R_`) | голоса дорожки → insert (drive, crush, gate) → фейдер → пан. **Без** посылов |
| `MOD`, `DLY`, `RVB` | `modfx_` / `delay_` / `reverb_` пишут возврат в обнулённый буфер отвода, затем он прибавляется к миксу | возврат шины целиком (все дорожки, что посылают). Сложение `m + (0 + r·g)` = `m + r·g` — мастер побайтно тот же |
| `MASTER` | после soft clip (как сейчас), но float до приведения к int16 | всё |

- Усиление стемов — тот же мастер-гейн `MAIN` (`mv × 0,25 / 100`), без компрессора, EQ и soft clip.
  Тогда при выключенных comp / EQ и без клипа `Σ T + MOD + DLY + RVB ≈ MASTER` (до округления).
- Компрессор и sidechain-ducking: на «сухих» стемах их нет — пэд, качаемый от бочки, в стеме не качает.
  Вариант «печатать мастер-компрессор»: `Compressor` уже считает один общий гейн на оба канала
  (каждые 8 сэмплов) — вывести его в массив блока и умножить на него отводы всех дорожек, кроме
  ключевой (она идёт мимо компрессора), и возвраты. Сумма тогда совпадает с мастером и по ducking.
  EQ (линейный) можно напечатать так же — 19 копий шелфов, офлайн это дёшево. Вопрос 2.
- **Отклонено:** «мокрый» стем с долей общей реверберации конкретной дорожки — нужна своя копия
  delay / reverb / MOD на каждую дорожку (×16 по CPU и RAM, delay с обратной связью и TAPE нелинейны).
  Сегодняшний STEMS (соло-проход на дорожку) именно это и приближает — ценой N проходов и суммы ≠ мастер.
  Оставить его режимом `STEMS WET` или убрать — вопрос 1.
- Какие дорожки получают стем: как `RenderDialog::stemTracks` — INT, слышимые (mute / solo), с нотами в
  используемых паттернах. В SONG дорожка, заглушённая в части слотов (`songMute`), в них молчит.
- Возвраты пишутся, только если шина включена и уровень > 0 (иначе файла нет).

## Проходы

Объём на проход: `24 бит стерео = 264,6 КБ/с звука` на файл. Полный набор (мастер + 16 + 3) = 20 файлов
= **5,3 МБ на секунду звука**; при скорости рендера 2× — 10,6 МБ/с на карту, мелкими кусками в 20 мест.

Решение — **адаптивно, по памяти буферов**:
- Буферы записи: на время экспорта PERF выключен (Render его и сейчас не включает), поэтому **кольцо
  PERF в PSRAM (≈1 МБ на 6 с)** отдаётся под буферы: 20 × 48 КБ. Запись кусками 32 КБ в заранее
  выделенные файлы (`FsFile::preAllocate` на оценку длины тела + максимум хвоста, `truncate` в конце) —
  последовательная запись без поиска кластеров; карта FAT32 / exFAT, SDIO.
- Без PSRAM (или после её сбоя): буферы из кучи RAM2, 8 КБ на файл, **до 6 файлов за проход**
  (48 КБ; сейчас Render берёт оттуда 16 КБ).
- Teensy сообщает ёмкость в ответе `RenderStart` (`outMax`); ESP раскладывает выходы по проходам:
  проход 1 — MASTER + возвраты + первые стемы, дальше стемы группами по `outMax`.
- Несколько проходов корректны **только благодаря детерминизму**: каждый проход рендерит весь микс,
  отводы берут разные дорожки, поэтому стемы разных проходов складываются в тот же мастер. Тест на это —
  обязательный (ниже).
- Время: с PSRAM — один проход; без — `ceil(N / 6)` проходов. Песня 4 мин, 16 стемов, без PSRAM:
  4 прохода × (2–4 мин) ≈ 8–16 мин. Прогресс один на все проходы (`EXPORT 2/4 37%`).
- Запись не должна ронять таймаут линка (`kBlocksMs` 1500 мс) и сторож (WDOG1 8 с): за один
  `RenderBlocks` сбрасывается не больше одного куска на файл, остальное — в следующих кадрах; полный
  сброс только на `RenderEnd` (он уже `requestLong` с `Progress`).
- Предварительно — `FsStat` с местом на карте: оценка `файлы × кадры × 6 Б` больше свободного →
  `DISK FULL` до старта, а не через 10 минут.

## Источник и длина

- **Source:** `PATTERN 01…16` или `SONG` (все слоты по порядку, как сейчас).
- **Loops** (только паттерн): 1, 2, 4, 8, 16. `RenderSpec::loops`, длина тела `passUs × loops`;
  в `Mode::Pattern` секвенсор и так крутит LOOP.
- **Tail:** `AUTO` (по умолчанию), `OFF`, `2 s`, `4 s`, `8 s`, `WRAP` (только паттерн).
  - `AUTO`: после тела рендер идёт, пока мастер не простоит ниже −60 dBFS (`kSilence`) 1 с, максимум
    30 с (delay с обратной связью 100 и freeze иначе не кончатся). Ответ `RenderBlocks` несёт счётчик
    тихих блоков; ESP перестаёт слать блоки, когда он ≥ 345. В конце все файлы режутся **на одну длину**
    (последний громкий блок мастера + 0,1 с), не каждый по своей тишине.
  - `WRAP` (бесшовная петля для сэмплов): рендерится `loops + 1` проходов, первый не пишется
    (`RenderStart::skipBlocks`), хвост последней петли тогда уже звучит в начале файла.
- Ноты, сдвинутые NDG / swing за конец, обрезаются — как сейчас.

## Формат, пути, имена

- WAV PCM, 44,1 кГц (частота синта), стерео, **24 бит по умолчанию**, `16 бит` опцией (с TPDF-дизером
  на детерминированном RNG; сегодня Render усекает без дизера). Мастер в 24 бит — из float до int16.
  Стемы с MAIN > 100 % могут выйти за 0 dBFS (soft clip на них нет): клип считается по файлу и
  показывается (`CLIP T03`). Float 32 для стемов — вопрос 3.
- `mtcr` (crc моно-микса) пишется только в мастер — для импорта в проект.
- Папка: `/export/<проект>/<SONG | P01 | P01x4>/`, файлы:
  `<проект>_<src>_MASTER.wav`, `<проект>_<src>_03_BASS.wav` (номер и имя дорожки `TrackCfg::name`,
  символы вне A–Z 0–9 _ - → `_`; без имени — `03`), `<проект>_<src>_FX_MOD.wav`, `_FX_DLY`, `_FX_RVB`.
  Длинные имена — LFN SdFat, путь < 128 (`RenderStartReq::path`). Префикс проекта в имени — чтобы файлы,
  вытащенные из папки, не путались.
- Перезапись: папка источника уже есть → один вопрос `OVERWRITE SONG?` на весь набор; старые файлы
  набора удаляются после успеха (пишем через `.tmp`, как сейчас).
- `/samples/render` остаётся для Resample (`resample.tmp`); FILE → SAMPLES → Import показывает и
  `/export` (проверить импорт 24-битного WAV в банк: превью 24 бит умеет).

## UI (ESP)

FILE → PROJECTS: пункт **Render WAV…** переименовывается в **Export…** (тот же `RenderDialog`, строки
добавляются; вопрос 6). Строки:

| Строка | Значения |
|---|---|
| Source | PATTERN 01…16 (звучащий) / SONG |
| Loops | 1 2 4 8 16 (только PATTERN) |
| Tail | AUTO / OFF / 2 s / 4 s / 8 s / WRAP |
| Tracks | ALL / SOLOED — что идёт в мастер (как сейчас) |
| Stems | OFF / TRACKS / TRACKS+FX |
| Format | 24 BIT / 16 BIT |
| EXPORT / CANCEL | |

- Под строками — оценка: `~63 MB x 20, 4:12, 2 PASSES` (по `songUs` / `passUs`, `outMax` из последнего
  `Hello` / `RenderStart`).
- Только при остановке (`STOP FIRST`), не в режиме Wi-Fi. Проект заблокирован на всё время
  (`engine::lockProject`, как сейчас) — правки, PERF, кнопки дорожек не действуют; энкодер / Play —
  только отмена.
- Прогресс `EXPORT 1/2 nn%` и прошедшее время; отмена — долгое нажатие энкодера или Play: `RenderEnd
  abort`, все `.tmp` набора удаляются, уже готовые файлы прошлых проходов этого запуска — тоже.
- Итог: `4:12 PEAK -1.3dB  17 FILES` (+ `CLIP`), ошибки — существующие `resultText`.

## Скачивание по Wi-Fi

Файлы на карте Teensy, браузер говорит с ESP → ESP проксирует через `remoteFs()`.

- Страница Wi-Fi получает раздел **Export**: список `/export/<проект>/<src>/` (`FsList`), размеры, ссылки.
  `GET /api/export/list`, `GET /api/export/file?path=…` — только внутри `/export` (`..`, абсолютные пути
  вне — 400; проверка в `lib/core` рядом с `webSynthFirmwareName`, тестируется). `Content-Length` из
  `FsStat`, `Content-Disposition: attachment`, поддержка `Range` (докачка оборванной загрузки).
- Отдача — цикл в обработчике: 4 КБ из `remoteFs` → `client.write`, прогресс на экране трекера
  (`DL 12/63 MB`), обрыв клиента — выход. UI-задача занята всё время скачивания (синхронный
  `WebServer`) — экран показывает только прогресс, EXIT обрывает.
- **Пропускная способность.** `FsRead`: 480 Б за запрос-ответ; ≈500 Б × 10 бит / 3 Мбод = 1,7 мс на линии
  + задержка опроса в `loop()` Teensy + чтение сектора ≈ **2,2–2,5 мс → ~200 КБ/с** (Wi-Fi ESP быстрее, узкое
  место — линк). Песня 4 мин: мастер 24 бит 63 МБ — **~5 мин**; полный набор 20 файлов 1,27 ГБ — **~1,8 ч**.
- Ускорители (вопрос 5):
  - `FsReadBurst`: один запрос — до 8 кадров подряд без ожидания (окно), Teensy читает 4 КБ за раз →
    ~280 КБ/с (предел 3 Мбод).
  - Поднять линк до 4–6 Мбод (echo-тест из плана 2026-10-09 так и не определил потолок; ESP32-S3 UART до
    5 Мбод) → ещё ×1,5–2. Затрагивает всё (события, стрим), только после стенда.
  - «Скачать всё» одним ZIP без сжатия (store, CRC32 на лету на ESP) — удобство, не скорость.
- Рекомендация в мануале: мастер — по Wi-Fi; набор стемов — вынуть карту.

## Протокол (link_msg)

**kProtocol +1** (другие ветки 2026-10-15 тоже поднимают — сводить при слиянии).

- `RenderStartReq`: `target = kExport` (новый), `dir[96]`, `bits` (16 / 24), `skipBlocks` (WRAP),
  `estFrames` (для `preAllocate`). Ответ `RenderRep` + `outMax`.
- Новый `RenderOut {idx u8, tap u8 (0 = MASTER, 1..16 = дорожка, 17..19 = MOD / DLY / RVB), name str}` —
  по одному на файл прохода, после `RenderStart` и до первого `RenderBlocks`; имя короче 64.
- `RenderRep` для `RenderBlocks` + `quiet u16` (тихие блоки мастера подряд). Для `RenderEnd`:
  `peak[20] u16`, `clips[20] u32` (≈120 Б, влезает в 512) и итоговые кадры (общие для всех файлов).
- `RenderEndReq`: `frames` — длина, до которой резать (общая для набора, считает ESP по `quiet`).
- `FsReadBurst` — только если выбран в вопросе 5.

## Взаимодействие

- **MIDI-дорожки** в экспорт не попадают (как сейчас): офлайн внешний синт не сыграет. В оценке
  показывать `MIDI TRACKS SKIPPED: 3`, если такие есть с нотами.
- **PERF** не участвует (буфер занят экспортом); удержанные кнопки снимаются при старте.
- **Живые контролы** заблокированы: проект под замком, транспорт стоит, ESP ждёт ответы Teensy.
  Метры MIX стоят.
- **Preview / превью сэмплов** останавливаются (`preview::stop()` уже есть).
- **Wi-Fi-режим** и экспорт взаимоисключающие (оба держат UI-задачу и линк); скачивание — только после.
- **SONG**: слоты по порядку, маски mute слотов применяются (`OfflineSequence::Guard` восстанавливает
  mute после). Петля песни / диапазон слотов — нет (YAGNI).
- **Sidechain**: ключевая дорожка идёт мимо компрессора и в мастер, и в свой стем; ducking — вопрос 2.

## Тесты (native)

`test_render` (расширить) / новый `test_export`:
- Отводы выключены и включены — мастер побайтно равен (живой путь не тронут).
- Comp 0, EQ плоский, MAIN 100, уровни без клипа: `Σ T + MOD + DLY + RVB` = мастер до soft clip
  (|разность| < 1e-5); с soft clip — мастер = `softClip(Σ)`.
- Печать компрессора: с comp и sidechain сумма = мастер до EQ.
- Проходы: набор, отрендеренный за 1 проход и за 4 (`outMax` = 6), побайтно одинаков.
- Возвраты: дорожка без посылов не меняет `DLY` / `RVB` / `MOD`; шина OFF — файла нет.
- `loops`: `blocksTotal = loops × pass + tail`; `WRAP`: файл = последняя петля, стык петли
  непрерывен (разность первого и сэмпла после последнего ≈ соседней).
- Автохвост: delay fb 0 → стоп ≈ через 1 с тишины; fb 100 → упор в 30 с; общий обрез всех файлов.
- `MultiWavWriter` на POSIX: 20 файлов, кусками, заголовки 16 / 24 бит читаются `wav.h`, truncate,
  отмена удаляет `.tmp`; нехватка места → ошибка без мусора.
- `ExportPlan`: раскладка, имена, санитайз имён дорожек, длина пути < 128.
- `test_link_msg`: `RenderOut`, новые поля, `kProtocol`.
- Путь веба: `/export/..` и чужие пути отклоняются; разбор `Range`.

На железе (`link_desk.py`): скорость рендера с PSRAM / без на 3 проектах; DEMO-HOUSE песней с полным
набором — сумма стемов против мастера в DAW (null-тест при comp 0); SmartBuy и Kingston; скорость
скачивания мастера по Wi-Fi.

## Риски

- **Карта:** 20 потоков записи — фрагментация FAT без `preAllocate` и провалы скорости на слабых картах
  (SmartBuy Blue уже давала отвалы). Не ломает результат (офлайн), но удлиняет; таймауты линка и WDOG1
  нужно держать кусками.
- **PSRAM CS0:** баг AHB timeout при записи наблюдали на CS1, на CS0 не перепроверен. Экспорт —
  интенсивная запись в PSRAM; без PSRAM путь через RAM2 и проходы обязателен и тестируется отдельно.
- **Скачивание медленное** (~200 КБ/с): стемы по Wi-Fi — часы. Честно написать в мануале.
- **Гонка `setLoad`** из ISR во время парковки (см. выше) — сейчас безвредна, закрыть флагом.
- **Рендер ≠ живой звук** там, где живой упирался в CPU-сторож (сторож офлайн не режет голоса) —
  экспорт может звучать полнее; бюджет по цене тот же.
- **kProtocol** поднимают несколько параллельных фич — конфликт при слиянии.
- RAM2: +48 КБ кучи на время экспорта без PSRAM; RAM ESP: `OfflineSequence` уже в PSRAM ESP.
- FAT32 4 ГБ на файл: 24 бит стерео — 4,5 ч, не достижимо (песня ≤ 128 слотов).

## Открытые вопросы

1. Стемы: сухие отводы + возвраты FX отдельными файлами, один рендер **[по умолчанию]**; или оставить
   и сегодняшний `STEMS WET` (соло-проход на дорожку со своей реверберацией) вторым режимом.
2. Мастер-обработка на стемах: без comp / EQ / clip **[по умолчанию]**; или печатать гейн компрессора
   (sidechain-качание попадёт в стемы, сумма = мастер).
3. Формат: 24 бит PCM для всех **[по умолчанию]**, 16 бит опцией; или стемы во float 32.
4. Проходы: один с PSRAM, группы по 6 без неё **[по умолчанию]**; или всегда один проход и экспорт
   стемов только с PSRAM.
5. Скорость Wi-Fi: как есть, `FsRead` ~200 КБ/с **[по умолчанию]**; `FsReadBurst` (~280 КБ/с); стенд
   4–6 Мбод.
6. Render WAV → Export с папкой `/export/<проект>/<src>/` **[по умолчанию]**; или оставить
   `/samples/render` и плоские имена.

## Решения (2026-10-15)

Дизайн принят со всеми рекомендациями; открытые вопросы закрыты так:

1. **Стемы — сухие отводы + возвраты FX отдельными файлами, один рендер.** Старый режим STEMS
   (соло-проход на дорожку) убран; Tracks = ALL / SOLOED решает только, что звучит в мастере.
2. **На стемах нет comp / EQ / soft clip**, только гейн MAIN. Печать гейна компрессора — нет.
3. **24 бит PCM для всех файлов**, 16 бит опцией (TPDF-дизер на детерминированном xorshift, своё зерно
   на файл: проходы дают те же байты). Float 32 — нет.
4. **Один проход с PSRAM** (буферы — кольцо PERF, до 20 файлов по 48 КБ), **без PSRAM — по 6 файлов за
   проход** (буферы из кучи RAM2 по 10 КБ; если malloc не даёт — меньше файлов, Teensy сообщает `outMax`).
5. **Wi-Fi как есть** (`FsRead`, ~200 КБ/с): на странице Wi-Fi раздел Export (список и скачивание с
   `Range: bytes=N-`), без `FsReadBurst` и без смены скорости линка. Мануал: стемы — вынуть карту.
6. **Render WAV… → Export…**, папка `/export/<проект>/<SONG | P01 | P01x4>/`.

Решения по ходу реализации (вопросы не задавались):

- **Отводы только читают микс.** Возврат = микс после шины минус микс до неё (копия в буфер отвода до
  `process`, разность после), а не «возврат в нулевой буфер + сложение»: компилятор сливает
  `mix += y * wet` в FMA (ARM64 нативно, Cortex-M7), и `m + (0 + y·w)` ≠ `fma(y, w, m)` — мастер
  разошёлся бы в младших битах (тест это поймал). Разность даёт ошибку порядка ulp микса (≈ −140 дБ),
  мастер не трогается вовсе. Отводы дорожек — та же `panAdd` в свой нулевой буфер.
- Отводы — по указателю `Synth::setTaps(RenderTaps*)`; в ITCM только проверки `taps_` и вызовы, сами
  функции (`tapsClear` / `tapTrack` / `tapReturn`) — в `synth.cpp` вне `MT_HOT`, т. е. во flash.
  Буферы отводов (1 КБ на выход) — `malloc` в RAM2, не PSRAM (их пишет каждый сэмпл `runStrip`).
- **`mtcr` в файлы экспорта не пишется** (заголовок RIFF + fmt + data, 44 байта): данные 24 бит, а
  crc банка считается по int16 моно — неверный ключ при импорте хуже, чем его отсутствие (импорт
  посчитает crc сам).
- **Длина — в кадрах виртуальных часов рендера** (блок `kRenderBlockUs` = 2902 мкс = 128 кадров):
  тело = `passUs × loops` в кадрах. OFF и WRAP — ровно тело (файл петли равен длине паттерна в
  тактах); 2 / 4 / 8 с — тело + N × 44 100; AUTO — `max(тело, последний громкий блок + 35 блоков)`,
  рендер до 1 с тишины (345 блоков) или до 30 с хвоста. Тишину считает Teensy по int16 мастеру
  (`RenderFeeder::loudBlocks`), отвечает `quiet` на каждый `RenderBlocks`. Проходы 2+ рендерят ровно
  столько блоков, сколько первый, и режут на те же кадры.
- WRAP: рендерится `loops + 1` петель + 1 блок, первая петля пропускается (`skipFrames`).
- `kTailBlocks = 500` (1,45 с при «2 с» в мануале) убран вместе со старым диалогом: строка Tail, 2 s =
  ровно 88 200 кадров; Resample хвоста не имеет (как и было).
- ISR `setLoad` во время парковки не вызывается (`audio_out.cpp`: только `!parked_`).
- Буферы записи: файл пишется кусками от порога (буфер − 6 КБ, т. е. ≥ 42 КБ с PSRAM, ≥ 4 КБ без),
  по одной записи на файл за `RenderBlocks`; `preAllocate` по оценке длины (ошибка не фатальна),
  в конце `truncate`. PERF на время экспорта отцеплен от синта (`setPerfBuffer(nullptr)`), после —
  возвращён очищенным. Отказ PSRAM-сторожа во время экспорта → `WRITE FAILED`.
- Перезапись: папка источника есть → `OVERWRITE <src>?`; после успеха лишние `.wav` папки (дорожки,
  которых больше нет в наборе) удаляются. Отмена / ошибка: `.tmp` прохода удаляет Teensy, готовые
  файлы прошлых проходов этого запуска — ESP.
- Имена: `<проект>_<src>_MASTER.wav`, `<проект>_<src>_03_<ИМЯ>.wav` (имя дорожки, A–Z 0–9 _ -, иное →
  `_`; без имени — `<проект>_<src>_03.wav`), `<проект>_<src>_FX_MOD|DLY|RVB.wav`. Возврат получает файл,
  если шина включена (MOD не OFF) и её уровень > 0.
- Веб: `GET /api/export/list` (JSON: файлы `/export/**`, рекурсивно на 2 уровня), `GET
  /api/export/file?path=` (только `/export/…`, без `..`; проверка `mt::webExportPath`, тест в
  `test_file_rules`). Пока идёт отдача, UI-задача занята (синхронный `WebServer`).
- `kProtocol` 11: `RenderStartReq` + `bits`, `outs`, `skipFrames`, `estFrames`, цель `kExport`;
  новый `RenderOut`; `RenderRep` + `quiet`, `outMax`, `outN`, `peaks[]`, `clipsN[]`;
  `RenderEndReq` + `frames`.
- Импорт (FILE → SAMPLES → Import) по-прежнему ходит только по `/samples`: `/export` в нём не виден.
  Вернуть экспорт в проект — скопировать файл в `/samples` на компьютере (или Resample). Отложено.
- Скачивание по Wi-Fi: `GET /api/export/list` отдаёт JSON `[{"p":путь,"s":размер}]` (chunked, обход
  `/export` на 3 уровня), `GET /api/export/file?path=` — 200 или 206 с `Content-Range` по `Range:
  bytes=N-` (`N` ≥ размера → 416), `Content-Disposition: attachment`, `audio/wav`. Отдача 4 КБ
  кусками `remoteFs` → `WiFiClient::write`, на экране `DL n/m MB` (хук `busy`), в журнале `+ download`
  / `! download …: cut off`. Отмены с трекера (EXIT) во время отдачи нет: её обрывает браузер (закрыть
  вкладку / отменить загрузку) — синхронный `WebServer` не даёт UI-задаче опросить кнопки. Страница
  сама читает список при открытии, кнопка Refresh — повторно.
- Мануал: старая фраза «с хвостом 2 с» (`kTailBlocks`) заменена строкой Tail; в мануале описаны ровно
  значения кода (AUTO: 1 с тишины ниже −60 dBFS, максимум 30 с, срез +0,1 с; 2 / 4 / 8 с — ровно).
