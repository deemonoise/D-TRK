# Загрузка CPU в статусбаре — дизайн

**Цель:** показывать загрузку аудио-рендера в верхнем статусбаре на всех вкладках.

- **Метрика:** средняя загрузка за окно ~500 мс: сумма времени рендера / (число блоков × длительность блока `kBlock / kRate` = 4 мс).
  Аудио-задача (единственный писатель) копит `sumUs`, `blocks`, `peakUs` в `std::atomic<uint32_t>`; UI раз в 500 мс
  забирает их со сбросом (`exchange(0)`) через `audio::takeLoad()`.
  Если за окно не было блоков (аудио выключено) — показывать последнее значение.
  (Раньше показывался пик блока — заменено на среднее, перегрузку отмечает цвет.)
- **Вид:** `CPU nn%` на правом краю (x=416). `PLAY/STOP` и `L…` сдвигаются левее, чтобы всё влезло в 480 px.
  Цвет: красный, если за окно был блок дольше периода (4 мс, перегрузка) или среднее ≥ 85 %; жёлтый ≥ 60 %; иначе `kDim`.
- **Обновление:** `App` раз в 500 мс берёт `takeLoad()`; если процент или цвет изменились — `dirty_ = true`.
- **Toast:** как сейчас — скрывает правую часть статусбара, CPU тоже.
- **PROJ:** CPU из шапки убирается (`cpuPercent`, `cpuShown_`, `cpuMs_`, `kCpuRefreshMs`, `wantsRedraw`).
- **Бенч:** `AUDIO_BENCH`/`AUDIO_BENCH_FM` пишут свой пик в Serial как раньше, независимо.
- **Тесты:** логика UI/аудио только в прошивке; проверка — сборка `wt32` и native-тесты без регрессий.
