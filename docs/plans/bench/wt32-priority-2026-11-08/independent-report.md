Проверен TUTU-TUDUTU, P01/LOOP, seed0x5EED:8с прогрева и3×8с последовательных профилей. Итоги взвешены по числу аудиоблоков; FPS вычислен из общего числа отправленных кадров и sampled_ms. Во всех9 окнах размещение памяти соответствует политике, получены DONE и возврат штатного Wi-Fi.

Нормализованный semantic model_fnv во всех случаях4363edfc, размер исходной сериализации66420байт. A2/B2 raw FNV также совпал06a49af7; C2 raw7943afbc отличается ожидаемо из-за хвоста имени после NUL. Host oracle воспроизводит это: autoload копирует неинициализированные байты name[12..15], saveProject включает их и зависимый CRC. Диагностический helper зануляет только post-NUL байты PROJ.name и исключает четыре производных CRC bytes (hash_excludes_crc=1); live Project не меняется. Исходный файл SD до/после проверен root без изменений. Первые A/B с разными raw FNV оставлены как preliminary, итоговое сравнение основано на A2/B2/C2.

Ограничения: это один проект и24с измерения на образ, не оценка максимальной полифонии или всех проектов. Target PCM побитово не сравнивался. Peak B2 по-прежнему выше4мс, поэтому отдельные yellow окна остаются. Пороги индикатора и способ чтения Load не менялись: yellow означает среднее≥60% либо peak>4мс за500мс. Видимая доля yellow не равна средней загрузке CPU. Stalls0 относятся к измеренным окнам.

Карточные SD.totalBytes/usedBytes сохранены в A2/B2 как в ручном SYSTEM; C2 снимает только повторение этих вызовов. Arduino вызывает FatFS f_getfree, но физическое чтение карты каждый кадр не доказано из-за возможного FAT-кэша. Диагностические controller/metadata/cache helper не предназначены для normal release. Production builder/device operations выполнял root; независимый parser исходники и устройства не менял.
