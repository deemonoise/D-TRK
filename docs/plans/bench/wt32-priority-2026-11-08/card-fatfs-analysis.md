**Что кэшируется.** f_getfree возвращает fs->free_clst без полного сканирования, когда free_clst <= n_fatent-2. После успешного подсчёта записывает найденное значение обратно в free_clst и помечает FSINFO dirty. Реальные [create_chain](/private/tmp/dtrk-sd-capacity-audit/create_chain.asm) и [remove_chain](/private/tmp/dtrk-sd-capacity-audit/remove_chain.asm) поддерживают известный счётчик при выделении/освобождении кластеров; обычная запись не означает полного FAT scan при следующем draw.

В SDK CONFIG_FATFS_DONT_TRUST_FREE_CLUSTER_CNT=0 и DONT_TRUST_LAST_ALLOC=0; [FF_FS_NOFSINFO](/Users/deemonoise/.platformio/packages/framework-arduinoespressif32-libs/esp32s3/include/fatfs/src/ffconf.h:302) разрешает использовать пригодный FAT32 FSINFO. При неизвестном/непригодном счётчике, например после mount без валидного FSINFO или FAT12/16, первый f_getfree сканирует FAT. Это секторные чтения через move_window; при dirty metadata window возможен и предварительный sync_window с disk_write. После успешного первого вызова второй обычно использует уже найденный счётчик. При disk_status/reinitialization/I/O failure возможен более дорогой путь mount/recovery; утверждать полный FAT scan на каждом кадре нельзя.

Вложенные SPI param/bus locks ждут portMAX_DELAY: [SPI.cpp:199](/Users/deemonoise/.platformio/packages/framework-arduinoespressif32/libraries/SPI/src/SPI.cpp:199), [SPI HAL](/Users/deemonoise/.platformio/packages/framework-arduinoespressif32/cores/esp32/esp32-hal-spi.c:1320). SD select может ждать busy до 500 ms; command retry содержит delay100 ms. Это ошибочные/занятые сценарии, а не измеренная типичная задержка CMD13. Прямого SD volume lock в Synth нет; причинность оставшихся yellow windows докажет только actual B/C, не этот call graph.

**Узкая production-политика.** Card formatter читает только snapshot в памяти. Новое состояние относится к устройству/UI, не Project: не вызывает markDirty и не меняет формат проекта. Snapshot содержит total/free, valid, pending и mount generation. Refresh выполняется из poll/job completion только при остановленном транспорте, вне capture CPU profile и вне активной записи/передачи; во время playing никаких вызовов SD capacity. Не переносить query в timer, который продолжает работать при playing.

| Событие | Действие |
|---|---|
| mount/remount/format/retry | Сбросить весь snapshot, включая total; запросить refresh после завершения mount/mkdir либо при первом безопасном SYS poll |
| save/autosave/export/record/bounce/render/sample or WT extraction, preset/template/log append | Пометить free pending после завершения batch/close, включая partial failure: временный файл уже мог занять кластеры |
| delete, truncate, rename/replace, directory creation/removal, Wi-Fi upload/delete | То же; после Wi-Fi close запросить refresh даже если изменился не открытый MTP |
| SD I/O failure / removed card | Снять valid; не показывать ошибочный used=0 как 100% свободного места |
| вход в SYS | Запросить refresh при dirty/unknown; пока playing использовать прошлый snapshot или неизвестное значение |
| только чтение / flash-bank compact/clear без SD-записи | Capacity не меняется; не связывать этот кэш с Project editSeq или flash-bank generation |

Для узкого внедрения без широкого перехвата всех File.write полезен резервный TTL 2–5 секунд только когда SYS видим и транспорт остановлен. Он покрывает пропущенные источники SD mutation, а явные hooks обеспечивают немедленное обновление после известных операций. Для конкурирующих writers generation до/после refresh позволяет не потерять новое dirty событие. Непрерывно свежая информация о физическом извлечении карты без I/O невозможна; mount/I/O-error события должны инвалидировать snapshot.
