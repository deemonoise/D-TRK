# Фильтр, DRUM 808/909, пресеты — дизайн

Дата: 2026-10-05. Продолжение [FM-машин](2026-10-05-fm-machines-design.md) и пунктов «фильтр на все типы» и «машины 808/909» из [future-audio.md](future-audio.md). Все цифры по CPU — оценки до замера.

## Решения

| Вопрос | Решение |
|---|---|
| Фильтр | SVF (LP / BP / HP) + своя AD-огибающая + keytrack, на всех типах |
| Локи фильтра | fx `FLT` (cutoff) и `RES` |
| LFO | открыт всем типам; новая цель CUTOFF; макро-цели — только FM и DRUM |
| 808/909 | новый тип `DRUM`, свой движок «аналоговых» моделей, 16 машин |
| Макросы DRUM | те же 5 слотов и fx `DEC COL SHP SWP CON`, имена — под машину |
| Пресеты | заводские в прошивке (только чтение) + свои на SD |
| Папки | `/presets/<TYPE>/<CATEGORY…>/NAME.mti`, вложенность до 4, как `/samples` |
| Заводские | 32: 10 CHIP, 10 FM, 12 DRUM, разложены по категориям; SAMPLE — без заводских |
| SAMPLE-пресет | сэмпл из пресета, если он есть в банке; иначе остаются текущие сэмпл и root |

## 1. Фильтр

### Поля `Instrument` (однобайтовые)

| Поле | Диапазон | Смысл |
|---|---|---|
| `fltMode` | `FltMode` Off, Lp, Bp, Hp | Off = обход |
| `cutoff` | 0..127 | 20 Гц × 700^(v/127): 20 Гц…14 кГц |
| `reso` | 0..127 | Q = 0,5 × 40^(v/127): 0,5…20 |
| `fenv` | −64..63 | глубина огибающей, ±6 октав |
| `fAtk`, `fDec` | 0..127 | время по `envTimeMs`; спад — экспонента до −60 дБ |
| `keytrack` | 0..127 | 0…100 %: октава ноты от C4 сдвигает cutoff на ×keytrack октав |

По умолчанию `fltMode = Off`, `cutoff = 127`, `reso = 0`, `fenv = 0`, `fAtk = 0`, `fDec = 40`, `keytrack = 0`. Старые проекты звучат бит-в-бит.

### Синт

- В `Voice`: `Svf flt`, `uint32_t fenvT` (сэмплов от note-on), `bool fltOn`.
- Control-rate (1 мс), только при `fltMode != Off`: октавы = `log2(cutoffHz(cut)/20)` + `fenv/64 × 6 × filterEnv(t)` + `keytrack/127 × (pitch − 60)/12` + LFO CUTOFF (±64 единицы cutoff). Затем `flt.set(mode, hz, resoQ(res))`. `tanf` — 1 раз в мс на голос.
- Рендер: голос пишет сегмент во временный буфер `tmp[kControl]` (как FM сейчас), фильтр идёт по `tmp`, потом сумма в микс. Фильтр стоит после VCA. Для линейного фильтра разница незаметна, зато один путь для всех типов.
- У FM внутренний SVF шума остаётся, новый фильтр стоит после всего голоса. У DRUM — тоже после голоса.
- `fenvT` сбрасывается на note-on без легато, `flt.reset()` — на новом голосе.

### Локи `FLT`, `RES`

Fx в конце `Fx` (после `CON`), 0..127. Семантика как у макро-локов: шаг с нотой — на ноты шага, шаг без ноты — на звучащие голоса дорожки до следующей ноты. `TrackRt::lockMask` и `Voice::lockMask` расширяются: биты 0..4 — макросы (только FM и DRUM), бит 5 — cutoff, бит 6 — reso (все типы). `lock[]` — 7 значений.

### LFO для всех типов

`lfo()` переезжает из `controlFm` в общий `control()`: цели PITCH, VOL, CUTOFF работают на всех типах. Макро-цели (DEC…CON) — только у FM и DRUM, у CHIP / SAMPLE UI их пропускает. Фаза LFO сбрасывается на note-on для всех типов. `LfoDest::Cutoff` — в конец перечисления (значения хранятся в файлах).

### Файл

Чанк `FLTR`: count + 16 записей по 8 байт (mode, cutoff, reso, fenv, fAtk, fDec, keytrack, резерв). Старые прошивки пропускают; файл без `FLTR` — значения по умолчанию.

## 2. DRUM

### Модель

- `InstrType::Drum` (перед `Count`).
- `enum class DrumMachine : uint8_t { Bd8, Sd8, Tom8, Cp8, Rs8, Cl8, Cb8, Hh8, Cy8, Bd9, Sd9, Tom9, Cp9, Rs9, Hh9, Cy9, Count }` — новые только в конец.
- Поля `machine` и `macro[5]` общие с FM; смысл зависит от типа. `drumSetMachine(m, machine)` ставит машину и её макросы по умолчанию.
- `instrSetType(m, type)`: при переходе в FM / DRUM ставит машину (клампит номер) и её макросы по умолчанию — смысл макросов разный.
- Чанк `FMIN` хранит `machine` 0..15; после загрузки FM с `machine ≥ 8` → 0.

### Движок `synth_drum.{h,cpp}`

`DrumParams` (control-rate) → `DrumVoice` (на сэмпл). Узлы, каждый со своей экспоненциальной огибающей (до −60 дБ):

| Узел | Что | Цена |
|---|---|---|
| tone[2] | синус, огибающая питча (полутоны, время), общая для обоих | 2 × ~8 |
| click | шумовой бёрст 1–4 мс + импульс в момент удара (909) | ~5 |
| metal | 6 квадратов на частотах набора × pitch → BP1 + BP2 → HP | ~60 |
| noise | xorshift → SVF (режим, частота, Q), бёрсты для клэпа | ~15 |
| drive | `tanh`-аппроксимация над суммой | ~5 |

Набор частот metal 808: 205,3 / 304,4 / 369,6 / 522,7 / 540 / 800 Гц (из схемы TR-808). CB8 берёт только 540 и 800. 909-хэты и тарелки в оригинале — сэмплы; здесь — другой негармоничный набор (263 / 400 / 421 / 474 / 587 / 845 Гц × 2) с большей долей шума и HP выше.

Голос «готов», когда все огибающие < −80 дБ. Всё ограничено: выход ∈ [−1, 1] после drive, без NaN.

### Машины `synth_drum_machines.{h,cpp}`

`drumMachine(machine, mac[5], pitch, out)` — чистая функция, как `fmMachine`. Нота C4 играет базовую высоту машины, остальные — относительно неё (тоны и металл). DECAY для всех: `fmDecayMs` (5 мс…4 с).

| SD8 | 180 / 330 | тон | TONE: баланс низ/верх | SNAPPY: шум 0…1 | SWEEP 0…7 пт | N.DEC: шум 0,3…2 × DECAY |
| TOM8 | 110 | тон | NOISE 0…0,3 | DRIVE | SWEEP 0…7 пт | TIME |
| CP8 | шум BP | хвост | FREQ 600…2500 Гц | SPREAD: 3 бёрста, 6…14 мс | Q 1…6 | TAIL 0…1 |
| RS8 | 500 / 1700 | 10…120 мс | TONE: баланс | NOISE | SWEEP | — |
| CL8 | 2500 | 10…120 мс | TONE ±1 октава | DRIVE | SWEEP | — |
| CB8 | 540 / 800 | хвост | FREQ BP 1,5…4 кГц | BAL: 540 ↔ 800 | ACCENT: пик 15 мс | — |
| HH8 | metal 808 | 20 мс…2 с | HP 4…12 кГц | NOISE: металл ↔ шум | SPREAD: ×0,8…1,25 | N.DEC: шум 0,3…1,5 × DECAY |

### Синт

- Все DRUM-машины: one-shot, моно на дорожке, choke с fade (как FM-ударные). Note-off игнорируется.
- Лимит тяжёлых голосов: `kFmVoiceMax` = 8 считает FM + DRUM.
- Макро-локи `DEC…CON` действуют на FM и DRUM.
- Кэш параметров не нужен: `drumMachine` дешёвая. Если бенч покажет обратное — кэш как у FM.

Оценка: ~60–100 тактов на голос, 8 голосов ≈ 5–8 % ядра.

### UI (INST, тип DRUM)

MACHINE, 5 макросов с именами из таблицы, затем общий хвост (фильтр, LFO). A, D, S, R, MODE, GLIDE — серые.

## 3. Пресеты

### Формат `.mti`

```
"MTI1"  u8 version=1  u8 type  u16 reserved
INST record (48 байт, как в .mtp)
FMIN record (16)
FLTR record (8)
u32 crc32 всех байт до него
```

Итого 84 байта. Упаковщики записей выносятся из `project_io.cpp` в общий `inst_codec.{h,cpp}`. `loadPreset` при ошибке не трогает `out`. Значения клампятся так же, как при загрузке проекта.

### Применение

`applyPreset(dst, src, sampleFound)`: копирует всё. Исключение — SAMPLE без сэмпла в банке: `dst.sample` и `dst.root` остаются прежними.

### Заводские

`presets_factory.{h,cpp}`: таблица `{type, category, name, fill(Instrument&)}` во flash. `fill` — функция без захвата, задаёт поля поверх значений по умолчанию (+ `fmSetMachine` / `drumSetMachine`).

| Тип | Категория | Пресеты |
|---|---|---|
| CHIP | LEAD | SQ LEAD, ARP PLK |
| CHIP | BASS | TRI BASS, ACID |
| CHIP | PAD | PWM PAD, WT PAD |
| CHIP | KEYS | WT BELL |
| CHIP | PERC | NOIS HH, NOIS SN, METALBL |
| FM | DRUMS | KICK, SNARE, CLAP, HAT C, HAT O, WOODBLK |
| FM | KEYS | BELL, E.PIANO, CHORD M7 |
| FM | BASS | FM BASS |
| DRUM | 808 | BD808, BD808 L, SD808, CH808, OH808, CP808, CB808 |
| DRUM | 909 | BD909, SD909, CH909, OH909, CP909 |

Значения стартовые, тембры подбираются на слух на железе. В коде DRUM получил 12 пресетов (добавлены CH909 и CP909 — пара к 808-м).

### Хранение (SD)

- `sdBegin` создаёт `/presets` и `/presets/CHIP|SAMPLE|FM|DRUM`.
- Вложенность папок внутри типа — до 4 (как `/samples`). Имена файлов и папок — `storage::validName` (≤ 16).
- Запись: `NAME.tmp` → проверка чтением → rename в `NAME.mti` (перезапись — удалить старый, затем rename).
- Wi-Fi: раздел «Пресеты (/presets)» с подпапками, загрузка только `.mti` ≤ 1 КБ. Проверка `loadPreset` на tmp-файле до переноса.

### UI

Шапка INST: `◀ INS3 NAME ▶ [PRESET] [PREVIEW]`. PRESET (тап или Shift + долгое нажатие энкодера) → меню LOAD / SAVE.

Браузер (`PresetBrowser`, на всю рабочую область):

- Шапка: `◀ TYPE ▶` (в LOAD — переключение типа, по умолчанию тип инструмента), путь, кнопки.
- Корень типа: строка `[FACTORY]` (только LOAD), затем свои папки (`name/`), затем файлы. Внутри — `..` первой строкой. FACTORY — виртуальная папка с категориями заводских.
- **LOAD.** Поворот или тап по файлу — пресет сразу применяется к инструменту и играет C4 (живое прослушивание). Клик по файлу — взять и закрыть. Кнопки в шапке: OK — оставить, DEL — удалить свой файл (подтверждение меню), CANCEL — отдельная явная кнопка, возвращает исходный инструмент (как и долгое нажатие). Клик или тап по папке — войти.
- **SAVE.** Тип — тип инструмента, FACTORY не показывается. Кнопки SAVE (клавиатура с именем инструмента → файл в текущей папке; если есть — меню «перезаписать?»), +DIR (клавиатура → новая папка), CANCEL. Клик по файлу — записать поверх (с подтверждением). Имя файла становится и именем инструмента (первые 8 символов).
- Последняя папка запоминается на тип (в RAM).
- Запись в проект — под `engine::lockProject()` + `markDirty()`. CANCEL после живых проб откатывает и `editSeq` (`rewindEditSeq`), если ничего больше не правилось.

## 4. Тесты (native)

- `cutoffHz`, `resoQ`, `filterEnv`: границы, монотонность.
- Синт: LP с низким cutoff режет пилу; Off = те же сэмплы, что без фильтра; огибающая открывает фильтр; локи `FLT`/`RES` с нотой и без; LFO CUTOFF и PITCH на CHIP.
- DRUM-ядро: синус-тон на нужной частоте; metal без NaN; бёрсты; `done()`; выход ограничен.
- Машины: все 16 × крайние макросы × ноты 24..108 — без NaN/inf, частоты < 0,45 × rate.
- DRUM в синте: моно + choke, note-off игнорируется, лимит тяжёлых голосов, локи DEC на DRUM.
- Формат: `FLTR` туда-обратно, файл без `FLTR`, DRUM-тип и машина 15 туда-обратно, FM с машиной 12 → 0.
- Пресеты: туда-обратно, плохая CRC / магия / версия / обрезка — `out` не тронут; `applyPreset` для SAMPLE с сэмплом и без.
- Заводские: ≥ 10 на CHIP / FM / DRUM, 0 на SAMPLE; имена уникальны в типе, ≤ 8 символов; тип записи = тип таблицы; поля в диапазонах (пресет переживает pack → unpack без изменений); каждый звучит (рендер ноты C4 не тишина).

## 5. Риски

- CPU: фильтр ~15–20 тактов на сэмпл на голос + `tanf` раз в мс; 16 голосов с фильтром — несколько процентов. Проверить бенчем вместе с DRUM.
  Бенч (`-DAUDIO_BENCH_DRUM`): 8 DRUM-голосов (по машине на дорожку, ретриггер каждую 1/16) + 4 CHIP POLY с резонансным LP и огибающей на preview-дорожке, а не 8 + 8: DRUM-нота моно забирает самый новый голос своей дорожки, и с дорожек паттерна оставшийся пул не занять; на одной дорожке POLY — максимум `kPolyPerTrack` = 4.
- Тембры 808/909 — приближение; доводка на слух на железе.
- Живое прослушивание в браузере пишет весь `Instrument` без атомарности: аудио-задача может прочитать смесь старых и новых полей на 1 мс. Допустимо (запись под `lockProject`, как правка имени).
