# SONG Page Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the chain-in-BANK song mode with a Polyend-style SONG tab: slots = pattern + per-slot mute mask, SONG/LOOP chosen by the transport, no song-mode flag in the project.

**Architecture:** `mt::Project` gets `song[] / songMute[] / songLen`. The sequencer gets a runtime song flag (`setSong(on, slot)`) that replaces `Project::songMode`. Old fields stay until Task 5, so each task compiles on its own. A new `ui::SongScreen` holds the editor. BANK loses the chain list and scenes.

**Tech Stack:** C++17, PlatformIO, ESP32-S3 Arduino + LovyanGFX. Native unit tests (Unity) in `test/`, core logic in `lib/core/src`.

**Design:** `docs/plans/2026-10-12-song-page-design.md` (read it first).

**Commands:**
- All native tests: `pio test -e native` (run from repo root).
- One suite: `pio test -e native -f test_sequencer`.
- Device build: `pio run -e wt32`.

**Commits:** none per task. One commit at the end, after the user's hardware check (project rule).

**Code style:** match the surrounding code. Short comments only where the code is not obvious, namespaces `mt` (core) and `ui`, 2-space indent, 120 cols.

### Task 2: Project file — SNG3 chunk and migration

**Files:**
- Modify: `lib/core/src/project_io.h`, `lib/core/src/project_io.cpp`
- Test: `test/test_project_io/test_main.cpp`

**Spec:**
- New chunk `SNG3`: `count u8`, then per slot `pattern u8, mute u16 LE` (3 bytes). Use `readRecords` with max `kSongMax`; pattern clamped with `clampu(b, 0, kPatterns-1)`.
- Save:
  - write `SNG3` from `songLen/song/songMute`;
  - stop writing `CHN2` and `SCNS`;
  - `PROJ` keeps its size, but writes `songMode=0`, `chainLen=0` and a zero chain.
- Load: `CHN2`, `SCNS` and the PROJ chain are parsed into a local `LegacySong` and are no longer written into the old `Project` fields:
  ```cpp
  struct LegacySong { int n = 0; uint8_t pat[64], rep[64], scene[64]; int8_t tr[64]; uint16_t scenes[8]; bool chn2 = false; };
  ```
  Initialize scenes to `0xFFFF` (empty). A PROJ chain fills it only if `CHN2` has not been seen; `CHN2` replaces it.
- At the `CRC ` chunk, if no `SNG3` was read and `legacy.n > 0`, migrate:
  - for each item: `rep` copies (`rep` 0 counts as 1), capped at `kSongMax` slots in total;
  - mask: scene `s` in 1..8 whose `scenes[s-1] != 0xFFFF` gives `scenes[s-1]`; otherwise the previous slot's mask (first slot: 0);
  - if any `tr != 0`, set `notes->songTransposeDropped = true`.
- API: `struct LoadNotes { bool songTransposeDropped = false; };` and `LoadErr loadProject(ByteSource& in, Project& out, LoadNotes* notes = nullptr);`.
- `readScns` and `readChn2` now fill the `LegacySong` and get it as a parameter.

**Steps:**
1. Failing tests:
   - (a) round-trip: song of 3 slots with masks → save → load is equal.
   - (b) build an old-format file by hand: `CHN2` with items {P1 x2 S1}, {P2 x1 S-}, {P3 x1 tr+2 S2}, with `SCNS` written **after** `CHN2` (scene 1 = 0x0003, scene 2 empty). Expect slots P1,P1,P2,P3 with masks 3,3,3,3 and `songTransposeDropped == true`.
   - (c) a PROJ-only chain (no CHN2) migrates with masks 0.
   - (d) more than 128 expanded slots are capped at 128.
   - (e) a saved file has no `CHN2` and no `SCNS` chunk.

   The existing old-format tests in this file may help as builders. Old tests that check `chainTr` and so on after load must now check `song`/`songMute`; update them.
2. Run `pio test -e native -f test_project_io`. Expected: FAIL.
3. Implement.
4. Run `pio test -e native`. All suites must pass, because other suites (demos, templates) may save/load. Then `pio run -e wt32`.

### Task 3: Sequencer — runtime song mode on the new fields

**Files:**
- Modify: `lib/core/src/sequencer.h`, `lib/core/src/sequencer.cpp`
- Modify: `lib/core/src/render.h`, `lib/core/src/render.cpp`
- Test: `test/test_sequencer/test_main.cpp`, `test/test_render/test_main.cpp`

**Spec:**
- Rename `ChainOp` → `SongOp` (same values) and `chainEdited` → `songEdited`.
- New API:
  ```cpp
  // SONG (on, with songLen > 0) or LOOP. Stopped: start() plays slot `slot` (clamped). Playing: takes
  // effect at the end of the pass (unheard steps are replanned): on = slot `slot` follows, off = the
  // heard pattern keeps looping. Paused: as playing, on resume.
  void setSong(bool on, int slot);
  bool song() const { return song_; }
  ```
- Fields `bool song_ = false; uint8_t songFrom_ = 0;`. `songActive()` = `song_ && songLen() > 0`, where `songLen()` clamps `p_.songLen` to `kSongMax`, and `chainAt(i)` → `songAt(i)` reads `p_.song`.
- `start()`: if `songActive()`, then `songPos_ = min(songFrom_, songLen-1)`, `cur_ = songAt(songPos_)` and `applyMute(songPos_, now)`.
- `endOfPass()`, song branch, with no repeats:
  ```cpp
  songPos_ = songPos_ < 0 ? (songFrom_ < songLen() ? songFrom_ : 0) : (songPos_ + 1 < songLen() ? songPos_ + 1 : 0);
  ```
  then `next = songAt(songPos_)`, `applyMute(songPos_, t)`, and if `next == cur_`, `next = -1` (so it goes on like a loop).
- `applyScene` → `applyMute(slot, t)`: always writes all 16 `tracks[].mute` from `p_.songMute[slot]`, with `pushOff` for tracks becoming muted. Keep the `sceneSet_`/`Sched::scene` undo mechanics (rename to `muteSet_`/`mutes`, and keep the existing `mutes` field that already stores the mute bits).
- Delete: `rep_`, `Sched::prevRep`, `chainRep()`, `chainTranspose()` and the transpose part of `adjustStep`. In `songEdited`, drop the `rep_ = kChainRepMax` line: the playing slot deleted makes the next one start at the pass end, because the remap puts `songPos_` at `at-1`.
- `showStopped()`: no longer forces slot 0. `songPos_ = -1`, `heardSong_ = -1`, `cur_` unchanged.
- `queuePattern()`: ignored only when `state_ != Stopped && songActive()`. Stopped, it always works, so the UI can show a slot's pattern.
- `setSong` while playing: `emitDue`, then `rewind`; if anything was rewound, `tag_` and `releaseAllTies` like `songEdited`. Then set the flags. If turned off, `songPos_` stays until `endOfPass` sets -1 (existing else-branch).
- Render:
  - `songTicks` sums `passTicks` over the slots.
  - `Guard` no longer touches `songMode` and only restores mutes.
  - `OfflineRender` calls `seq_.setSong(spec.mode == RenderSpec::Mode::Song, 0)` before `start`.
- Update the long comment above `class Sequencer` to describe slots, masks, `setSong`, and that there are no repeats or transpose.

**Steps:**
1. Rewrite the song tests in `test_sequencer` on the new fields and API. All 93 chain/scene references go: delete the repeat/transpose/scene-empty tests, convert the rest.

   New tests:
   - start with `setSong(true,2)` plays slot 2 first;
   - the song wraps to slot 0;
   - a slot mask is applied at the slot start, with NoteOff for a newly muted track;
   - live `tracks[t].mute` changed mid-slot is overwritten at the next slot;
   - `setSong(false)` while playing keeps looping the heard pattern;
   - `setSong(true,k)` while looping goes to slot k at the pass end;
   - stopped `queuePattern` works with `song_` on;
   - deleting/inserting above the heard slot keeps the position;
   - two equal adjacent slots keep TIE (no release).
2. Run `pio test -e native -f test_sequencer`. Expected: FAIL.
3. Implement. Then update `test_render` (song length = sum of slot passes, mutes restored).
4. Run `pio test -e native`. Expected: all PASS.

   Device: `src/engine/engine.cpp:59` must use `songEdited` / `SongOp`. Rename `Cmd::ChainEdit` → `Cmd::SongEdit` in `engine.h/.cpp` and update its users (`src/ui/app.cpp`, `src/ui/bank_screen.cpp`).   - Row: slot number `%02d`.
    - Heard slot: `kPlayBg` row background, number text `kCursor`, and a bar under the number cell with width ∝ `status.pos / pattern length`.
    - `Pxx` in `kText`.
    - Cells: track plays → `fillRect` in `kText` (or the existing track colour if there is one, see `theme.h`); muted → `drawRect`; no data → a 2x2 dim dot (muted + no data: dim `drawRect`).
  - Cursor `drawRect` in `kCursor` around the (row, column) cell; in pattern edit, `kEditCursor`.
  - Empty song: one row `+ ADD Pxx` (heard pattern).
  - Masks per pattern: cached `uint16_t masks_[kPatterns]` via `mt::patternTrackMask`, refreshed on `onEnter` and `onPatternChange`.
  - Input:
    - `EncTurn`: row (or pattern ±1 in edit; `shift` → column).
    - `EncClick`: on PAT toggle pattern edit, on a cell toggle mute.
    - `EditTurn`/`EditEnd`/`EditCancel` (A chords) = pattern edit with revert, as BANK's row edit did.
    - `EncLong`: row menu.
  - Touch:
    - Tap a cell: cursor there, toggle mute on a track cell.
    - Tap PAT of the selected row: cursor there.
    - Vertical drag that starts on PAT of the selected row: pattern ±1 per `kRowH` px.
    - Drag elsewhere: scroll.
    - Long tap: row menu.

    - `Insert Pxx above` (Pxx = heard pattern, mask 0).
    - `Delete`.
    - `Mutes <- live` (mask from `tracks[].mute`).
    - `Clear mutes`.
    - `Clear song` (confirm item `Clear song: sure?`, like BANK's Clear).
  - Every write is under `engine::lockProject()`, followed by `engine::post(Cmd::SongEdit, (row << 8) | op)` while still holding the lock (op Insert/Delete/Edit as the old BANK code did), then `unlockProject` and `app_.markDirty()`.

  - `onProjectReplaced`: cursor 0, scroll 0, clear the undo ring.
  - `wantsRedraw`: when `songPos` or `pos` changed (progress bar).
  - `cursor()` returns the selected row (0 when empty).
