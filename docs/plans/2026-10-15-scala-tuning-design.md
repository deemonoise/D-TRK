# Микротональный строй (Scala .scl) — дизайн

Статус: **принят** (2026-10-15: пользователь принял все рекомендации, вопросы 1–6 — вариант (а)). План:
`2026-10-15-scala-tuning.md`.

## Цель

Встроенный звук (INT-дорожки) играет не только в 12-TET: проект выбирает строй — `12-TET` (по умолчанию,
ровно сегодняшнее поведение, бит-в-бит тот же звук) или таблицу ступеней (заводскую или пользовательский
файл Scala `.scl` с карты). MIDI-выход не меняется.

## Что выяснилось в коде (и поправки к исходной постановке)

- **Высота у всех типов считается из одной точки.** `Synth::control()` (synth.cpp ~1078) собирает дробный
  номер ноты `pitch` = `v.pitch` (нота + transpose + fine + слайд/глайд) + `r.bend` + смещение ARP + VIB +
  LFO PITCH/FINE и раздаёт его дальше: `controlFm / controlSyn / controlMacro / controlString` (через
  `noteHz`), CHIP (`cachedHz`), SAMPLE (`pitch - root` → `exp2`), фильтр (key tracking). Значит, строй
  встраивается **одним отображением в `control()`**, движки не трогаются.
- **Формат проекта:** чанки, неизвестные пропускаются; `kProjectVersion = 1`, а файл с версией выше
  текущей старая прошивка **отвергает** (`BadVersion`). Существующая схема расширения — новый чанк без
  смены версии (так добавлены TINS, TFOL, PRF2, SNG3…). Поэтому версию **не поднимаем**: новый чанк `TUNE`,
  старая прошивка его пропустит и сыграет проект в 12-TET (мягкая деградация, а не отказ открыть файл).
- **Связь ESP → Teensy:** `SynthModel` зеркалится чанками (`synth_model.h`: Master, Tracks, Instr0+i,
  Samples, Wavetables), `StateMirror` шлёт грязные чанки, на Teensy `onStateSet` делает `memcpy` в модель
  (под `__disable_irq`). Синт читает модель напрямую (`p_`). Значит, таблица строя — новое поле
  `SynthModel` и новый чанк зеркала; состояние SYNC работает само (`kChunks` растёт).
- **Wi-Fi-страницы Presets нет.** Веб-страница (`src/net/web*.cpp`) — только обновление прошивки; файлы
  пресетов, ARP/PRG/BAS переносятся картой через компьютер. Поэтому `/presets/TUN` — папка на карте
  (создаётся при монтировании, как папки типов), без веб-страницы (см. вопрос 5).
- **Имена пользовательских файлов** листаются `storage::listTexts` с `validName`: до 16 символов,
  `A–Z a–z 0–9 _ -`. Файлы Scala-архива с точками/пробелами в имени не видны — их надо переименовать
  (в руководство).

## Решения

### Отображение клавиш (linear mapping)

Таблица `.scl`: N ступеней `c[1..N]` в центах, `c[N]` — период (обычно 1200, у Бохлена–Пирса 1901.96).
`c[0] = 0`. Корень R — MIDI-нота, которая **сохраняет свою 12-TET высоту**. Для клавиши k:

```
j = k - R;  q = floorDiv(j, N);  d = j - q*N
pitch(k) = R + (q * c[N] + c[d]) / 100        // полутоны, дробный «MIDI-номер»
off[k]   = pitch(k) - k
```

Каждая следующая клавиша — следующая ступень, период повторяется. Клавиатурные карты `.kbm` не
поддерживаются (YAGNI, в future). При N = 12 (JI, пифагорейский, мезотон, Веркмейстер) раскладка привычная:
те же клавиши, другие интервалы. При N ≠ 12 (19/24/31-EDO, слендро, пелог, BP) на «октаву» клавиатуры
приходится N клавиш; названия нот в GRID остаются 12-тоновыми (ограничение).

### Где применяется (по типам)

| Тип / случай | Строй | Почему |
|---|---|---|
| CHIP (вкл. шумовые волны) | да | мелодический генератор, шум тоже идёт от высоты ноты |
| SAMPLE, высота от ноты | да | `semis = T(key) - root`: нота root звучит так же, как 12-TET-нота R |
| SAMPLE, срез по ноте (`slicePitch`) | нет | нота выбирает срез, высоты нет |
| FM, машины TONE / CHORD (`fmGated`) | да | мелодические |
| FM, барабанные машины (KICK…HAT) | нет | одноразовые барабаны, как DRUM (вопрос 2) |
| SYNTH, MACRO, STRING | да | |
| DRUM | нет | |
| Полосы KIT (любой тип в полосе) | нет | нота полосы — выбор звука |
| MIDI-выход (EXT) | нет | будущее: MPE / pitch bend / MTS |

Флаг голоса `Voice::tuned` ставится на note-on (тип подходит **и** строй проекта не 12-TET) и не меняется до
следующей ноты. Голос с `tuned = false` идёт старым путём без единой изменённой операции — отсюда бит-в-бит
12-TET. Переключение строя во время звучащей ноты действует со следующей ноты (у `tuned`-голоса таблица
берётся живая, так что смена таблицы между двумя нестандартными строями слышна сразу).

### Порядок модификаторов высоты (tuned-голос)

- **В пространстве клавиш** (до отображения): нота, transpose (в ступенях), SLD / Glide / fx-слайды,
  смещения ARP и аккорда ARP+CHD. Глайд идёт по `v.pitch` в клавишах, а `T()` между целыми клавишами
  линейно интерполирует `off[]` — концы глайда точно на ступенях строя, путь непрерывен.
- **В реальных полутонах** (после отображения): fine (центы, вопрос 3), pitch bend, VIB, LFO PITCH / FINE.
  Вибрато и LFO одинаковой глубины во всех строях.
- Для tuned-голоса note-on кладёт в `v.pitch` и `r.lastPitch` ноту + transpose **без** fine; fine
  добавляется в `control()` из инструмента (побочно: правка Fine слышна сразу, а не со следующей ноты).

```
kp    = v.pitch + arpOff                     // клавиши
pitch = T(kp) + fine/100 + bend + vib + 12*la[Pitch] + la[Fine]
T(x)  = x + off[i] + (x - i) * (off[i+1] - off[i]),  i = floor(x)
```

### Стоимость на Teensy

- В синте массив `float off_[128]` (512 Б) — смещение каждой MIDI-клавиши, пересчитывается только при смене
  таблицы. Клавиши вне 0..127 (transpose + ARP у краёв) — по периоду: `off(k ± N) = off(k) ± (c[N]/100 - N)`
  (редкая ветка).
- Смена таблицы: синт держит копию поля `tuning` (~276 Б) и раз за блок (128 сэмплов) делает `memcmp` с моделью;
  при отличии — пересчёт `off_` (128 × несколько операций, без `exp`). Так не нужен хук из `link_server`,
  оффлайн-рендера и тестов — синт самодостаточен. Цена `memcmp` ≈ доли мкс на блок.
- На голос за control-обновление: floor, два чтения, lerp — порядка 10 тактов. Посемплово ничего.
- RAM1 (DTCM) +~0.8 КБ; ворота RAM1/ITCM из плана A task 1 проверяются после задачи синта; прогон
  `teensy41-bench` на регресс (ожидается в пределах шума).
- Замер (2026-10-15, после фичи; в скобках — база до неё): `teensy41` RAM1 variables 222816 (220992),
  code 247056 (246480), padding 15088 (15664), free for local variables 39328 (41152); ITCM code + padding =
  262144 = 256 КБ — ворота пройдены, free ≥ 24 КБ. FLASH code 314976. `teensy41-bench`: RAM1 variables 223104,
  code 249584, padding 12560, free 39040. `wt32`: RAM 128188, Flash 1519271. Парсер `.scl` и заводские
  тексты на Teensy не линкуются (только ESP); `TuneMap::build`, `tuningValid` — во flash (холодный код).
  Переменных +1.8 КБ: модель + копия `tuneSeen_` + `off_[128]`.

### Модель и файлы

```
constexpr int kTuneDegMax = 64;
struct TuningTable {              // в SynthModel, в конце (после wavetableCount)
  char name[17] = {};             // "12-TET" не хранится: count == 0 значит 12-TET
  uint8_t count = 0;              // ступеней в периоде, 0 = 12-TET, 1..64
  uint8_t root = kTuneRootAuto;   // MIDI-нота 0..127 или 0xFF = AUTO (вопрос 1)
  uint8_t pad = 0;
  int32_t mc[kTuneDegMax] = {};   // ступени 1..count в 1/1000 цента; mc[count-1] = период
};
```

- Миллиценты (int32), а не float: точно переносимо, ошибка 19/31-EDO < 0.001 цента.
- Проверка: `count` 1..64, период > 0 и ≤ 4800 центов, |ступень| ≤ 9600 центов; немонотонные ступени
  допустимы (как в Scala).
- Корень AUTO = C-4 + Scale root (60..71): чистый строй звучит в тональности проекта (вопрос 1).
- **Файл:** чанк `TUNE` (u8 count, u8 root, name 16 Б, count × i32) пишется только при count > 0, так что
  12-TET-проект сохраняется байт-в-байт как сейчас. Нет чанка → 12-TET. Битый чанк (count вне 1..64, длина
  не та, период ≤ 0) → 12-TET и `LoadNotes::tuningDropped` (тост `TUNING RESET`), без отказа загрузки.
- Проект хранит имя и разрешённую таблицу: играет без `.scl` на карте. Правка `.scl` на компьютере не меняет
  проекты; чтобы подхватить её, выбрать строй заново.
- Строй — свойство проекта: не входит в пресеты инструментов; шаблоны и демо — 12-TET; новый проект —
  12-TET. Экспорт WAV (рендер на Teensy) звучит в строе; экспорт MIDI — нет.

### Связь

- `Chunk::Tuning = 4`, поле в конце `SynthModel`; `kChunks = 5 + kInstruments`; порядок отправки Master,
  Tracks, **Tuning**, инструменты, Samples, Wavetables (строй до первых нот). 276 Б — один кадр `StateSet`
  (≤ 480).
- `kProtocol 7 → 8`; `sizeof(SynthModel)` растёт, проверка `Hello::modelSize` уже ловит несовпадение
  прошивок (`Mismatch`) — шить обе.

### Парсер `.scl` (lib/core, `scala.h/.cpp`)

`ParseErr parseScl(const char* text, int len, SclTable& out, int* errLine)` по спецификации Scala:
- строки, начинающиеся с `!`, — комментарии (в любом месте файла); CR/LF/CRLF;
- первая некомментарная строка — описание (может быть пустой; сохраняется в `out.desc`, 32 символа, для тоста);
- вторая — число ступеней (ведущие пробелы, хвост после числа игнорируется);
- затем ровно столько строк высот: первое слово; с `.` → центы (знак допустим, `5.` и `.5`
  допустимы); иначе отношение `a/b` или целое `a` (= a/1), a и b > 0 и < 2³¹; хвост строки игнорируется;
  центы = 1200·log2(a/b) в double, округление до миллицента;
- лишние строки после последней ступени игнорируются.

Ошибки (с номером строки): `NoCount` (нет строки с числом), `BadCount` (не число / отрицательное), `Empty`
(0 ступеней), `TooMany` (> 64 → тост `TOO MANY NOTES (MAX 64)`), `BadValue` (не число, `a/0`, `0/b`,
отрицательное отношение, переполнение), `Truncated` (ступеней меньше заявленного), `BadPeriod` (период ≤ 0
или > 4800 центов), `TooBig` (файл > 8 КБ при чтении). Тосты `BAD SCL L12` и т. п.

### Заводские строи (`tuning_factory.cpp`)

Хранятся как тексты `.scl` и разбираются тем же парсером (заодно тест парсера на реальных данных):

| Имя | N | Период | Источник |
|---|---|---|---|
| JUST 5-LIMIT | 12 | 2/1 | 5-limit хроматика: 16/15 9/8 6/5 5/4 4/3 45/32 3/2 8/5 5/3 9/5 15/8 |
| PYTHAGOREAN | 12 | 2/1 | 3-limit, волчья квинта G#–Eb |
| MEANTONE 1/4 | 12 | 2/1 | четвертькоммовый мезотон, Eb..G# |
| WERCKMEISTER3 | 12 | 2/1 | хорошая темперация (12 клавиш, все тональности играбельны) |
| 19-EDO / 24-EDO / 31-EDO | 19 / 24 / 31 | 1200 | равномерные |
| SLENDRO | 5 | 1200 | приближение гамелана (≈ 0 231 474 717 955) |
| PELOG | 7 | 1200 | приближение гамелана (≈ 0 120 270 540 670 785 950) |
| BOHLEN-PIERCE | 13 | 3/1 | JI-вариант BP (27/25 25/21 9/7 7/5 75/49 5/3 9/5 49/25 15/7 7/3 63/25 25/9 3/1) |

Порядок в списке: 12-TET, заводские (как в таблице), затем файлы `/presets/TUN` по алфавиту (до 64).

### UI (ESP, PROJ, страница SONG)

После `Scale` две строки:
- **Tuning** — имя строя; энкодер листает `12-TET` → заводские → файлы карты, выбор применяется сразу
  (файл читается через удалённую ФС и разбирается; ошибка → тост, остаётся прежний строй). Список файлов
  читается один раз при первой правке строки за визит экрана. Если строя проекта нет в списке (файл удалён
  или проект с другой карты), строка показывает его имя — таблица играет из проекта.
- **Tuning root** — `AUTO` (C-4 + Scale root) или нота `C-0..G-9`; неактивна (серая) при 12-TET.

Undo — как у соседних строк PROJ (`markDirty`). Кнопки дорожек (ступени лада), мини-клавиатура и названия
нот в GRID остаются 12-тоновыми; квантование `Scale` работает по клавишам, а не по высотам строя.

### Карта

- `/presets/TUN/NAME.scl`: плоская папка (без подпапок, как ARP/PRG/BAS); создаётся на Teensy в
  `fs_server makeFolders()` вместе с папками типов. Пользователь копирует файлы с компьютера.
- Только чтение: сохранять `.scl` из трекера нечего (редактора строя нет).

## Решённые вопросы (2026-10-15, все — вариант (а))

1. Корень по умолчанию — **AUTO = C-4 + Scale root**; явная нота — по выбору.
2. FM строится только для TONE / CHORD; барабанные FM-машины — нет; шум CHIP — да.
3. Fine в строе — центы поверх строя.
4. Выбор строя — строка PROJ, энкодер листает и сразу применяет.
5. `.scl` попадают только через карту (Wi-Fi-загрузки нет).
6. Заводские строи из таблицы, без строки опорной частоты. (В вопросе было «11» — ошибка счёта: в таблице 10
   строев; реализован ровно набор таблицы.)
