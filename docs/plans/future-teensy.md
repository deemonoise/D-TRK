# Планы на будущее: синт-плата Teensy 4.1 + Audio Shield

Записано 2026-10-06. Идея: вынести синтезатор / сэмплер с ESP32-S3 на Teensy 4.1 (600 МГц Cortex-M7, FPU) с Audio Shield Rev D (SGTL5000: линейный выход, наушники, линейный / микрофонный вход). ESP остаётся секвенсором, UI, Wi-Fi, MIDI OUT. Это «вариант 2» из [future-audio.md](future-audio.md).

**Статус:** реализовано в ветке `feature/teensy`, но иначе, чем ниже: линк — UART 3 Мбод (GPIO 13/14), а не RS485; ЦАП — PCM5102A, а не Audio Shield; см. [дизайн](2026-10-09-teensy-synth-design.md) и [план](2026-10-09-teensy-synth.md). Остальное здесь — исходные заметки (цифры — оценки); открытыми остаются стриминг длинных сэмплов и аудиовход.

## Что даёт

- 44,1 кГц стерео, больше голосов, VA-осцилляторы, reverb / delay / send-шины без оглядки на CPU ESP.
- Длинные сэмплы и wavetable на собственной SD Teensy (SDIO, быстро), а не во flash ESP (сейчас ~9,9 МБ).
- Линейный выход и наушники вместо мостового NS4168.
- Аудиовход (запись сэмплов, обработка внешнего сигнала) — на ESP невозможен в принципе.

## Пины: свободных GPIO на WT32-SC01 Plus нет

Extended IO занят целиком (10 MIDI, 11–14 энкодер / Play, 21 Shift), Debug (43/44) — PCF8575. Рассмотренные каналы:

1. MIDI OUT (GPIO 10) напрямую на RX Teensy — ноль новых пинов, но односторонний, 31250 бод, параметры только через NRPN / SysEx. Не подходит: нужен обратный канал (список файлов с карты Teensy, «файл не найден», уровни записи).
2. **RS485 (GPIO 1 TX, 2 RX, 42 DE/RE — встроенный трансивер, линии A/B на разъёме)** — выбранный вариант. Двунаправленный полудуплекс, 1–2 Мбод, ничего не отнимает.
3. Освободить GPIO 21, перенеся Shift на свободный P1x расширителя — запасной обратный канал для варианта 1.
4. USB-host Teensy ↔ USB-device ESP (composite CDC + MIDI) — конфликт с логом / прошивкой и питанием, отклонён.

## Схема

```
WT32 A/B ──── MAX3485 (3,3 В) ──── Teensy Serial1 (RX 0, TX 1), DE/RE → GPIO 2
5 В (выход IP5306), GND ──── Teensy VIN, GND
```

- Четыре провода. Оба устройства 3,3 В, согласование уровней не нужно; пины Teensy не 5 В-толерантны.
- Если Teensy будет одновременно в USB компа при питании от платы — разрезать перемычку VUSB/VIN.
- Teensy ~100 мА на 600 МГц; потребление ESP при этом падает (нет аудио-задачи).
- Audio Shield занимает 7, 8, 20, 21, 23 (I2S), 18 / 19 (I2C), 6 (опциональная flash). Serial1 (0/1), Serial3 (14/15), Serial4 (16/17) свободны.
- USB-гнездо Teensy вывести наружу корпуса — запасной путь прошивки.
- NS4168 на плате остаётся: либо не используется, либо метроном / запасной выход.

## Две карты

- ESP: проекты `.mtp`, пресеты, как сейчас.
- Teensy: `/samples`, `/wavetables`, записи с входа. Проект хранит имена + CRC, как сейчас; Teensy отвечает на запрос «есть ли файл с таким CRC».
- Экран INST / браузер сэмплов берёт список с карты Teensy через линк (`ListDir`, постранично).
- Загрузка `.wav` через Wi-Fi: ESP принимает и стримит на Teensy (`FilePut`), Teensy пишет на свою карту. 1 МБ при 2 Мбод ≈ 5 с.

## Протокол линка

ESP — мастер, Teensy отвечает только на запрос (полудуплекс). Кадр: `[len][type][payload][crc16]`.

Типы (черновик): `Hello` (версии прошивки и протокола), `NoteOn / NoteOff / CC / PitchBend`, `InstParam` (при правке), `ProjectDump` (все инструменты при загрузке), `ListDir`, `FileInfo`, `FilePut / FileGet`, `RecStart / RecStop`, `Meter` (пиковые уровни входа / выхода), `FwChunk`, `Ack / Nack`.

- Несовпадение версии протокола при старте — экран «обновите Teensy» вместо тихих глюков.
- Тайминг: секвенсор тикает на ESP, джиттер UART на 1 Мбод — доли миллисекунды; задержка меньше нынешних ~14 мс INT.

## Прошивка

- Монорепо: `lib/core` общий (synth, synth_voice, synth_fm, sample_bank, wav — чистый C++), окружения `wt32`, `wt32-ota`, `teensy41`. `pio run` собирает оба, скрипт складывает `.bin` + `.hex` в один релиз.
- Teensy: свой класс `AudioStream`, `update()` заполняет блоки по 128 сэмплов. Teensy Audio фиксирован на 44,1 кГц — `kSampleRate` синта переводится с 32 кГц (или хак `setI2SFreq`).
- ESP: `src/audio` (I2S, аудио-задача, банк во flash) заменяется транспортом. Секвенсор уже ходит через `mt::MidiSink` — добавляется sink для линка. Плюс отправка `InstParam` при правке и `ProjectDump` при загрузке.

### Обновление Teensy через Wi-Fi

Teensy 4.1 штатного OTA не имеет, но есть **FlasherX** (joepasquariello/FlasherX): прошивка принимает Intel HEX потоком, пишет во вторую половину flash (8 МБ, образ синта влезает с запасом), проверяет, копирует поверх и перезагружается.

1. Web-страница `/firmware` принимает `.hex` для Teensy рядом с `.bin` для ESP (`webFirmwareName` расширяется). Возможен один zip: ESP распаковывает, шьёт Teensy, потом себя.
2. ESP стримит hex кадрами `FwChunk` с `Ack`, Teensy скармливает FlasherX. 300 КБ при 1 Мбод — пара секунд.
3. Teensy перезагружается, ESP ждёт `Hello` с новой версией, пишет в лог Wi-Fi.

Оговорки:
- Первый раз — по USB (Teensy Loader): нужна прошивка с FlasherX, чтобы было кому принимать.
- Кирпич невозможен: загрузчик в отдельном чипе MKL02, кнопка Program всегда возвращает USB-режим.

## Аудиовход

SGTL5000 на шилде: стерео линейный вход (пады LINE IN L / R) и моно микрофонный вход с питанием (пады MIC / GND). На ESP входа нет вообще (NS4168 — только усилитель, встроенный ADC ESP32 для звука непригоден).

Сценарии:
- **Запись сэмплов** прямо на карту Teensy: `RecStart` → Teensy пишет `/samples/rec_NNN.wav` (16 бит, 44,1 кГц, моно / стерео) → `RecStop` возвращает имя, инструмент SAMPLE его подхватывает. Уровень — `Meter` раз в ~20 мс, индикатор на экране ESP. Порог автостарта (запись с тишины до сигнала) — на Teensy.
- **Внешний сигнал через микшер**: вход как ещё один канал — фильтр, delay, reverb, громкость, mute. Фактически мини-микшер для внешнего синта / драм-машины на тот же выход.
- Sidechain / компрессор от входа — позже, если понадобится.

Железо: гнездо 3,5 мм TRS на LINE IN (уровень `lineInLevel(0–15)`, 0 = 3,12 В p-p … 15 = 0,24 В p-p); для микрофона — отдельное гнездо на MIC с `micGain`. Объекты Teensy Audio: `AudioInputI2S` → `AudioRecordQueue` (запись на SD) и → микшер выхода.

## Сделано: стриминг сэмплов с SD

Сделано 2026-10 (дизайн [2026-10-10-sample-streaming-design.md](2026-10-10-sample-streaming-design.md), план [2026-10-10-sample-streaming.md](2026-10-10-sample-streaming.md)): все сэмплы играют стримом с SD Teensy (хранилище `/mt-store/<crc>.wav`, пул 16 слотов × 6 КБ в RAM2, планировщик по запасу в `loop()`), «головы» во flash, упреждение `0xF4` от секвенсора, PSRAM (8 МБ) — кэш целых сэмплов со сторожем и буфер PERF 6 с. С 2026-10-14 только чип на площадке CS0 (штатная раскладка PJRC, его находит startup); своя инициализация CS1 удалена, без чипа на CS0 буферные эффекты PERF выключены. Лимит банка и запись сэмплов во flash ушли.

Замеры (desk, `link_desk.py bench-stream`): 16 голосов с SD, 600 с — 0 недогрузок, минимальный запас 25 мс, CPU 16 %; с PSRAM запас 30–37 мс; `--semis 12` (октава вверх) — запас 6 мс. RAM2 свободно 90 112 Б. PSRAM CS1 8 МБ, self-test 11,7 мс, кэш сэмплов 7154 КБ, PERF 6 с.

`bench-stream --heavy` (2026-10-14): 8 самых длинных файлов по 2 ноты на дорожках 0–7 (16 стрим-голосов) + 16 heavy на 8–15 (4 DRUM с ретриггером на 1/16 при 120 BPM, 4 FM TONE по 3 ноты), без drive / reverb / comp. Сборка `MT_NO_PSRAM`: 32 голоса, CPU 45,8 % среднее / 47,5 % пик, 0 недогрузок за 2×30 с, запас 26 мс.

Потолок голосов (2026-10-14, env `teensy41-bench-max`, `src/teensy/bench_max.cpp`: desk-сборка без USB-аудио и демо, пул поднят до 64 / 48 heavy; на каждом голосе drive 100, delay send 100, reverb send 100; delay fb 100, уровни 100, компрессор on; +4 голоса за шаг до порога защиты 80 %). Чистый предел: CHIP saw + резонансный LP — 48 (76,9 %, ≈1,5 % на голос); FM TONE — 32 (77,0 %, ≈2,3 %); WT SYNTH на двух wavetable — 28 (76,8 %, ≈2,6 %); DRUM с ретриггером 1/16 — 16 дорожек = 46 % среднее / 52,5 % пик (≈2,9 % на голос, предел раскладки, по CPU ≈24); 16 WT + CHIP — 36 (76 %). Delay + reverb + comp вместе ≈2,5 %, база без голосов 2,1 %. Вывод: текущие 32 / 16 в худшем случае (16 WT + 16 CHIP) дают ≈70 %, запас до защиты ≈10 %; поднимать общий пул выше ≈36 смысла нет, heavy-лимит 16 — по делу (28 WT уже на пороге). Замер `bench-stream --heavy --wt --fx` (16 стрим на 0–7 + 16 WT SYNTH на 8–15, drive / delay / reverb 100 на всех, comp): 70,1 % среднее / 70,7 % пик, 0 недогрузок за 30 + 60 с, запас стрима 14 мс (без --fx: 50,0 %, запас 21 мс). До защиты ≈10 %.

Известные проблемы:
- Исправлено: проверка карты (`mediaPresent`, CMD13) посреди открытой SDIO-передачи сдвигала данные, а неудачное чтение отравляло кэш SdFat (`FsCache::prepare`) — так портился каталог FAT. Теперь `syncDevice()` перед CMD13 (не чаще раза в 500 мс) и обёртка `SafeCard` в `fs_server.cpp`: одиночные чтения через отдельный буфер, 3 повтора, перемонтирование тома при окончательной ошибке. После фикса 16 импортов по 5 МБ подряд без сбоев (до — 1 из 5). Зависание драйвера в режиме FIFO (циклы ожидания без таймаута) закрыто сторожевым таймером WDOG1 (`src/teensy/wdog.*`): loop() не пришёл за 8 с — сброс платы; его кормят loop(), `link::statusIfDue()` (длинные операции за один заход) и перенос прошивки по страницам. Причину сброса Teensy пишет в лог при каждом Hello (`boot: the watchdog reset the board`); проверка — `LD hang`.
- При одновременной записи большого файла (импорт, Save, Wi-Fi, рендер) чтение карты блокируется на 150–430 мс: стрим-голоса в это время могут недогрузиться.
- Снято вместе с CS1 (2026-10-14): с PSRAM на CS1 `bench-stream --heavy --sd` вешал плату. Блок рендера раз в несколько секунд длится ≈1,07·10⁹ тактов (≈1,8 с), всё время уходит в стадию `perf` (запись кольца PERF в PSRAM, `PerfBus::writeBuffer`), в `FLEXSPI2_INTR` взводится `AHBBUSTIMEOUT` (0x400). После нескольких таких блоков WDOG1 сбрасывает плату. Зависит от раскладки кода и тайминга: отладочные вставки в `synth_perf.cpp` прятали сбой, 1 нота на дорожку и обычный `bench-stream` не сбоят. С `MT_NO_PSRAM` сбоя нет. Причину таймаута AHB (конфиг FlexSPI2 / LUT записи / CS1 на плате с оторванной площадкой CS0) не нашли; поддержку CS1 убрали. На CS0 этот сценарий ещё не гоняли — повторить, когда будет плата с чипом на CS0.

Открыто: асинхронный DMA-ридер SDIO (если SmartBuy-класс карт понадобится на октаву выше; заодно снимет блокировку при записи), стерео-сэмплы.

## Порядок работ (когда дойдёт)

1. Железо: MAX3485, провода, Teensy с шилдом на макетке; эхо-тест RS485 на 1 Мбод.
2. Протокол + `Hello`, `NoteOn/Off` → Teensy играет `lib/core` как есть (моно, 32 → 44,1 кГц).
3. Карта Teensy: `ListDir`, `FileInfo`, `FilePut`; браузер сэмплов через линк.
4. `InstParam`, `ProjectDump`; удаление `src/audio` на ESP (или флаг сборки «внутренний звук» для платы без Teensy).
5. FlasherX + поле `.hex` на `/firmware`.
6. Аудиовход: запись, метр, канал внешнего сигнала.
7. Стерео, reverb, send-шины, VA — по [future-audio.md](future-audio.md).
