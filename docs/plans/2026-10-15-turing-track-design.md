# Живой генератор-регистр на дорожке (Turing-style) — дизайн

Статус: принят 2026-10-15 (все рекомендации, см. «Решения»); план — `2026-10-15-turing-track.md`.

Опирается на:
- секвенсор `lib/core/src/sequencer.{h,cpp}`: `scheduleStep` → `playTrackStep` / `skipTrackStep` →
  `expand` (`expandStep`, `step_expand.h`), история `Sched` и `rewind()` для перепланирования;
- ARS (`StepArp`) — образец «состояния дорожки, которое живёт между шагами и откатывается в `rewind`»;
- trance gate (`TrackCfg::gate*`, страница TRACK → INS, клетки `Steps`) — образец показа 16 клеток;
- формат файла: чанки с записями на дорожку (`TINS`, `TFOL`: count, record size, «длиннее / короче —
  берём что знаем»).

## Цель

Живой генератор мелодии в духе модуля-«машины Тьюринга»: зацикленный сдвиговый регистр длиной 2–16
бит. При каждом такте регистр сдвигается, выпадающий бит возвращается в начало; с вероятностью
**Flip** он при этом инвертируется:

- Flip 0 % — петля заперта: повторяется ровно каждые Length тактов;
- Flip 100 % — бит инвертируется всегда: петля тоже заперта, но вдвое длиннее (вторая половина —
  инверсия первой);
- середина — петля медленно мутирует (чем ближе к 50 %, тем быстрее).

Значение регистра превращается в ноту лада проекта в заданном диапазоне. Генератор **играет вживую** и
паттерн не трогает — этим он отличается от Fill / ARP / CHORDS / BASS (диалог Fill), которые один раз
пишут ноты в паттерн. Записать петлю в паттерн можно отдельно (Capture, см. ниже).

**Имена:** название модуля и производителя нигде не появляются (UI, руководство, changelog) — как правило
для движков MACRO / STRING. В UI: страница **GEN**, fx **FLP**, в руководстве — «генератор-регистр».

## Где живёт: настройка дорожки, не режим

Не новый тип дорожки и не новый `TrackOut`: это настройка дорожки на новой странице TRACK → **GEN**,
строка `Gen: OFF / PITCH / GATE`. Дорожка остаётся обычной (MIDI или INT, свой инструмент, insert,
follower, mute / solo), паттерн и все fx работают; генератор только подменяет высоту (PITCH) или ещё и
ритм (GATE).

Конфиг — **в `Project`, не в `TrackCfg`**: `TrackCfg` входит в `SynthModel` и зеркалится на синт-плату
чанком `Tracks`; генератор синт-плате не нужен. Отдельный массив (как `perfMap`) не меняет зеркало,
`kProtocol` и прошивку Teensy.

```cpp
// lib/core/src/model.h
enum class GenMode : uint8_t { Off, Pitch, Gate, Count };  // в файлах: новые значения только перед Count
struct GenCfg {
  uint8_t mode = 0;      // GenMode
  uint8_t len = 8;       // 2..16 бит
  uint8_t flip = 10;     // 0..100 %
  uint8_t low = 48;      // нижняя нота диапазона (C-3), приводится к ладу вверх
  uint8_t oct = 2;       // 1..4 октавы
  uint8_t density = 50;  // 0..100 %, только GATE
  uint16_t seed = 1;     // начальный регистр и ряд переворотов
};
// Project: GenCfg gen[kTracks];  Project::reset() — всё OFF, seed = номер дорожки + 1.
```

Генератор действует во всех паттернах и слотах песни (настройка дорожки, как Volume). На драм-дорожке
(`trackIsDrum`) не действует: страница GEN серая, `Gen` показывает `DRUM`.

## Регистр (чистые функции, `lib/core/src/shift_gen.{h,cpp}`)

```cpp
struct GenState { uint16_t reg; uint32_t n; };  // регистр и число сдвигов с Play
void genReset(GenState&, const GenCfg&, int track);          // reg = hash(seed, track) & mask, 0 -> 1
void genShift(GenState&, const GenCfg&, int track, uint8_t flip);  // flip 0..100 (FLP или cfg.flip)
uint8_t genNote(const GenState&, const GenCfg&, uint8_t root, ScaleType);
bool genGate(const GenState&, const GenCfg&);
```

- **Сдвиг:** `out = bit(len-1)`; `in = out ^ (hash(seed, track, n) % 100 < flip)`;
  `reg = ((reg << 1) | in) & mask(len)`; `++n`. Случайность — хеш от (seed, дорожка, n), **не**
  `rng_` секвенсора: `rng_` общий с PRB / NRN / VRN и не откатывается в `rewind`, а хеш даёт одну и ту же
  мелодию при любых правках PRB на других дорожках и при перепланировании.
- **Нота:** окно `w = min(len, 8)` младших бит → `v = window / (2^w − 1)` (0..1); ступеней в
  диапазоне `N = degrees(lad) × oct + 1` (верхняя тоника включительно); `idx = round(v × (N − 1))`;
  нота = `moveDegrees(low', idx, root, scale)`, где `low'` — `low`, поднятая до ближайшей ноты лада.
  Ноты выше 127 — октавой ниже. Лад — проектный (PROJ → Scale); Chromatic даёт все полутоны.
- **Гейт (GATE):** байт гейта — те же 8 бит в обратном порядке (старшие по времени биты весомее, чтобы
  гейт не повторял высоту: низкая нота ≠ «играет»); `gate = rev8(window) × 100 < density × 256`.
  Порог даёт монотонность: больше Density — добавляются удары, старые не пропадают. 0 % — тишина,
  100 % — каждый шаг.

## Секвенсор

Новое состояние `GenState gen_[kTracks]`, копия в `Sched` (`GenState gens[kTracks]`, как `arps`),
восстановление в `rewind()`. `start()` делает `genReset` всем дорожкам.

**Когда сдвигается регистр (такт):**
- **PITCH** — на каждом шаге дорожки **с нотой** (`hasNote()`), до проверки CND / PRB. Length = число нот
  в мелодической петле: паттерн с 4 нотами и Length 8 играет 8-нотную мелодию за два прохода. Шаг,
  не прошедший условие, «съедает» значение (ноту петли) — детерминированно.
- **GATE** — на каждом шаге дорожки (своём шаге: Speed x2 / 1/2 учитывается, `trackStepAt`).
- Регистр сдвигается и на заглушённой дорожке, и в `skipTrackStep` (пропущенные после затыка шаги):
  после unmute петля в той же фазе.
- Fx **FLP** на шаге: этот сдвиг идёт с вероятностью FLP вместо Flip дорожки (см. fx).

**Подмена шага** — в `playTrackStep` / `skipTrackStep` до `expand`, на копии `Step`; дальше всё как у
обычного шага:
- **PITCH:** у шага с нотой `note = genNote(...)`. Громкость, все fx (CHD, STR, RAT, GAT, TIE, ARS, NRN,
  локи) — шага. CHD строит аккорд от новой ноты (строчные типы — по ладу), NRN добавляет разброс сверху,
  ARS арпеджирует от неё, TIE связывает одинаковые соседние ноты. Шаги без ноты и OFF не меняются.
- **GATE:** нотная колонка паттерна игнорируется, кроме **OFF** (он снимает ноты как обычно). Если
  `genGate`, шаг получает `note = genNote(...)`, громкость — громкость шага (`...` = Def vel); fx шага
  (пустого или нет) действуют на эту ноту, как у ARS: CND / PRB шага решают, звучит ли удар, FLT / GAT /
  CHD — его локи. Нет гейта — шаг идёт как шаг без ноты (его контроллеры и локи уходят как сейчас).
  Ритм задаётся регистром, а паттерн — маской условий и локов поверх него.
- Транспонирование инструмента, глайд, Def gate — как у любой ноты. MIDI-дорожки играют то же самое на
  свой канал (подмена в секвенсоре, выход не важен); CHN работает.

**Смена паттерна, песня, пауза:** регистр продолжает идти (он у дорожки, не у паттерна; как часы trance
gate). Сбрасывается только `start()` — Play с остановки, <kbd>Shift</kbd>+<kbd>Play</kbd> (песня с
курсора), рестарт. Pause / resume — продолжает. Отдельной команды «сброс» нет: Reseed (см. UI) задаёт
новый seed и при игре сбрасывает регистр с ближайшего несыгранного шага.

**Правки на ходу:** Length, Low, Oct, Density, Flip, Mode применяются с несыгранных шагов (правка → `replan`,
как другие правки TRACK: unheard-шаги откатываются вместе с `gen_` и планируются заново). Уменьшение
Length обрезает старшие биты, увеличение добавляет нули сверху.

## Fx FLP

`Fx::FLP` (добавляется перед `Count`), значение 0–100, «оба» выхода. Лок шага: сдвиг регистра на
этом шаге идёт с вероятностью FLP вместо Flip дорожки. `FLP 0` на части шагов «прибивает» эти ноты
петли, остальные мутируют; `FLP 100` на одном шаге — гарантированный переворот. В PITCH на шаге без ноты
ничего не делает (сдвига нет); при Gen = OFF — серый. Синт-плате не отправляется (не synth fx).
`fx_info`: имя, описание, место в `kOrder` (группа «Случайность и условия», после NRN).

## Живое управление Flip

- TRACK → GEN → строка **Flip** (поворот, <kbd>A</kbd>+поворот, <kbd>Shift</kbd> ×10).
- **Кнопка дорожки N держать + клик энкодера:** сейчас переключает поворот VOL ↔ PAN; на дорожке с
  Gen ≠ OFF цикл становится VOL → PAN → FLIP (toast `TRK5 FLIP 30%`), на MIDI-дорожке с генератором —
  сразу FLIP (громкости и панорамы у неё нет, сейчас там `TRK5 MIDI`). Работает с любого экрана, где
  работает громкость с кнопки; новых жестов нет. Значение сохраняется в проекте, undo нет (как Volume).
- **Fx FLP** — запрограммированный «замок» по шагам (см. выше).
- В PERF не добавляется: PERF — эффекты на микс INT, генератор — секвенсор (YAGNI).

## Capture: петлю в паттерн

Пункт меню GRID **Capture gen** (виден на дорожке с Gen ≠ OFF; на драм-дорожке нет). Один шаг undo,
toast `GEN CAPTURED`, затем **Gen = OFF** у дорожки (иначе генератор продолжал бы подменять только что
записанные ноты; Flip / seed остаются, включить обратно — одной строкой).

- Состояние: при игре — `gen_` и `pos_` секвенсора (под тем же локом, что `queuePattern`; это уже
  спланированный, чуть впереди слышимого шаг), на остановке — `genReset` (= что сыграет Play).
- Чистая функция `captureGen(Pattern&, track, cfg, state, fromStep, root, scale)` в `lib/core`
  (`edit_ops`): проходит длину дорожки (Pat len) от `fromStep` по кругу, сдвигая копию состояния **с
  Flip 0** (FLP-локи шагов игнорирует) — записывается петля «как она сейчас», без будущих мутаций.
  - PITCH: ноты шагов с нотой заменяются, остальное не трогается.
  - GATE: шаг с гейтом получает ноту (громкость и fx остаются), шаг без гейта теряет ноту (fx остаются),
    OFF не трогается.
- Если Length не делит число тактов дорожки, записанная петля — это ближайший проход, а не вся петля
  регистра (руководство это скажет).

## Детерминизм, Render и Resample

- Render WAV и Resample идут через `Sequencer` с `start()`: регистр с `genReset`, переворот — хеш от
  seed, поэтому оба прохода Resample (замер и запись) и повторные рендеры дают одинаковые байты.
  Рендер звучит как «Play с остановки», а не как текущее живое состояние петли — это и есть
  предсказуемость; хотите зафиксировать живую — Capture.
- `rng_` не используется; PRB / NRN / VRN других дорожек мелодию не меняют. Одинаковые seed + Flip 0 —
  одна и та же петля при каждом Play.

## UI

**TRACK → GEN** (шестая закладка после NOTE: `MAIN INS FOL NOTE GEN MIDI`; работает на MIDI и INT,
серое только на драм-дорожке):

| Строка   | Значения                                   | По умолчанию |
|----------|--------------------------------------------|--------------|
| Gen      | OFF, PITCH, GATE                           | OFF          |
| Length   | 2–16                                       | 8            |
| Flip     | LOCK (0), 1–99 %, x2 INV (100)             | 10 %         |
| Low      | нота (`C-3`)                               | C-3          |
| Range    | 1–4 OCT                                    | 2 OCT        |
| Density  | 0–100 %, серая вне GATE                    | 50 %         |
| Seed     | 0–65535; клик — Reseed (новый случайный)   | дорожка + 1  |
| Register | Length клеток, только показ                | —            |

- **Register:** клетки как у Steps trance gate (залитая = 1), новый бит слева. Во время игры
  перерисовываются по слышимому шагу: `Sequencer` хранит в `Sched` состояние после шага, UI берёт
  состояние слышимого (`heardGen(track)`, как `heardPos`). Справа — нота, которую регистр даёт сейчас
  (`D#4`), в GATE — ещё точка гейта. Переворот последнего сдвига — клетка мигает жёлтым ~100 мс.
- **GRID:** на имени дорожки с генератором — метка `G` (Overview и Detail); ноты паттерна показаны
  как есть (это ритм / заготовка), в Detail на такой дорожке нотная колонка тусклее, чтобы было видно,
  что высоту задаёт генератор.
- Светодиодов у кнопок дорожек сейчас нет (пины расширителя заняты энкодером, Play, Shift), поэтому
  показ только на экране.

## Формат файла

- Новый чанк **`TGEN`**: count, record size, запись на дорожку: `mode, len, flip, low, oct, density,
  seed lo, seed hi` (8 байт). Правила как у `TINS` / `TFOL`: длиннее — берём известное, короче —
  недостающее по умолчанию; значения зажимаются (`mode >= Count` → OFF, len 2..16, flip / density
  0..100, oct 1..4, low 0..127). Пишется всегда.
- Старые файлы (без `TGEN`) — генераторы OFF, звучат как раньше. Старая прошивка пропускает `TGEN`
  (неизвестный чанк) и читает `FLP` в PATN как пустой слот (`cmd >= Count` → None): паттерн играет
  записанные ноты.
- Fx FLP хранится обычным слотом шага, `Step` не меняется. Пресеты инструментов и протокол связи не
  затрагиваются; `kProtocol` прежний, Teensy не перепрошивается.

## Память и CPU

- `gen_`: 16 × 8 Б в объекте `Sequencer` (внутренняя RAM); `Sched::gens`: 16 × 16 × 8 Б = 2 КБ в
  `Cold` (PSRAM допустима, см. `coldBytes`). Проверить, что `sizeof(Sequencer)` укладывается в блок
  `core_ram.cpp`.
- CPU: хеш и сдвиг на шаг дорожки — пренебрежимо.
- Сборки 2026-10-15 (задача 10): `wt32` — RAM 128676 Б (39,3 %), Flash 1537035 Б (18,5 %).
  `teensy41` — RAM1 code 248464 + padding 13680 = 262144 (8 банков ITCM), variables 222848, свободно под
  локальные 39296 Б (≥ 24 КБ); RAM2 variables 186624. `teensy41-bench` — RAM1 code 250992 + padding
  11152 = 262144, свободно 37984 Б. `shift_gen.cpp` и `sequencer.cpp` — холодные (во flash).

## Риски

- **Путаница «в GRID одни ноты, звучат другие»** — метка `G`, тусклая нотная колонка, Capture.
- **Откат `rewind`:** забытое восстановление `gen_` даст «плывущие» мелодии после любой правки во время
  игры — ловит тест «replan = без отката».
- **PITCH-такт по нотам** зависит от того, сколько в паттерне нот: правка ритма сдвигает фазу мелодии.
  Это поведение оригинала (такт = гейт), но неочевидно — в руководство.
- 6 закладок TRACK на 480 px — проверить ширину `PageBar`.
- `Sched` растёт на 128 Б × 16; если `Cold` во внутренней RAM на какой-то сборке — проверить запас.

## Не делаем (YAGNI)

Свой лад у генератора, ручная запись бит («write»-переключатели), второй выход (CC / модуляция),
генератор на драм-дорожке, отдельный on/off по паттернам, PERF-кнопка, синхронизация двух дорожек одним
регистром, сброс по смене паттерна.

## Решения (2026-10-15)

Приняты все рекомендации открытых вопросов:

1. Такт в PITCH — по шагам дорожки **с нотой** (Length = нот в петле). Шаг, не прошедший CND / PRB,
   «съедает» значение.
2. Gen — одна настройка дорожки на все паттерны и слоты песни.
3. Регистр сбрасывается только `start()` (Play с остановки, Shift + Play, рестарт); смена паттерна /
   слота песни, пауза — не сбрасывают.
4. Живое управление Flip: цикл VOL → PAN → FLIP по клику энкодера с зажатой кнопкой дорожки (на дорожке
   с Gen ≠ OFF), строка TRACK → GEN → Flip и fx FLP.
5. Capture записывает петлю и выключает генератор (Gen = OFF).
6. Имена в UI и руководстве: GEN / FLP, «генератор-регистр»; слово «Turing» — только в заголовке этого
   документа и в плане.

Решения по ходу реализации (без вопросов пользователю):

- `Fx::FLP` добавлен перед `Count` (значение 50 в enum). Синт-плата его не видит: `expand` шлёт на
  синт только `fxSynthOnly`, FLP туда не входит; Teensy и `kProtocol` (9) не меняются. Старая прошивка
  читает FLP как пустой слот (`cmd >= Count` → None).
- Цикл кнопки дорожки: на INT-дорожке с генератором VOL → PAN → FLIP → VOL, без генератора VOL ↔ PAN
  как раньше; на MIDI-дорожке с генератором поворот сразу FLIP, без генератора toast `TRK5 MIDI`. В виде
  SCENE (MIX) поворот с зажатой кнопкой по-прежнему меняет значение сцены (сцены забирают поворот раньше),
  клик энкодера переключает режим, как раньше. Чистая функция `holdNext` / `holdFirst`
  (`lib/core/src/shift_gen.h`) — тестируется в native.
- Живая правка Flip с кнопки и строки GEN — команда движка `Cmd::GenEdit`: перепланирует несыгранные
  шаги (`Sequencer::genEdited`, как `replan`, без снятия TIE). Reseed — `Cmd::GenReseed` (трек):
  перепланировка и `genReset` этой дорожки с новым seed.
- Шаг, подменённый в GATE без гейта, идёт как шаг без ноты (его fx и локи уходят как сейчас); нота
  шага без гейта снимается, шаг ведёт себя как пустой (держащийся TIE не отпускается, как на пустом шаге).
- Регистр сдвигается до `audible` / CND / PRB, в т. ч. на заглушённой дорожке, в `skipTrackStep`, и
  когда дорожка вне маски рендера (`setTrackMask`).
- `heardGen`: состояние после слышимого шага (из `Sched::gens` следующего шага или `gen_`), копия под
  локом проекта (`engine::genState`). Мигание переворота: бит `flipped` последнего сдвига в `GenState`.
- Capture при игре берёт `gen_` и шаг дорожки, с которого планируется следующий шаг (`trackStepAt` от
  `pos_` / `loop_`), если играет редактируемый паттерн; иначе — с шага 0. На остановке — `genReset`.
- Высота: `low'` — ближайшая нота лада ≥ Low; если `low' + 12·oct > 127`, весь диапазон опускается на
  октавы (ноты остаются в ладу).
