# SYNTH: классические осцилляторы + wavetable — дизайн

Дата: 2026-10-06. Статус: согласован, к плану.

## Цель

Новый тип инструмента `InstrType::Synth` для внутреннего звука: «аналоговые» пила/квадрат/треугольник
без алиасинга (PolyBLEP) и wavetable с морфингом по кадрам. Braids не портируем: классические формы —
малая часть Braids, внутри это тот же PolyBLEP; портирование стоило бы ~3–4 тыс. строк и адаптации
под 32 кГц ради моделей, которые не нужны.

Ограничения железа: ESP32-S3, 32 кГц, блок 128, 16 голосов, PSRAM 2 МБ (N16R2) уже занята больше
чем наполовину, раздел `samples` во flash 9,9 МБ (общий с сэмплами), app-раздел 3 МБ (прошивка 1,45 МБ).

## 1. Тип и голос

- `InstrType::Synth` — в конец enum (старые файлы не ломаются); в UI рядом с FM.
- Общее, как у всех типов: AHDSR громкости, SVF + огибающая фильтра, LFO, delay send, mono/glide,
  fx SLD/VIB/ARP/VSL/CUT/OFF.
- `Voice` получает `SynthVoice`: 2 осциллятора + sub + noise + свой AD «env→SHAPE». Рендер блоком
  в IRAM (`MT_HOT`), как `FmVoice`; параметры — на control rate в `Synth::control`.
- Режим каждого осциллятора:
  - BL Saw — PolyBLEP;
  - BL Square — PolyBLEP на обоих фронтах, PW 5–95 % (SHAPE);
  - BL Tri — leaky-интеграл квадрата или BLAMP (выбрать по бенчу/спектру);
  - WT — таблица + позиция SHAPE 0..63 кадра.
- WT: мип-уровень по частоте ноты, кроссфейд между двумя соседними уровнями, кроссфейд кадров,
  линейная интерполяция. 8 уровней: уровень k — гармоники до 128>>k, длина кадра max(256>>k, 64)
  точек (сумма 768 точек на кадр) ≈ 96 КБ на таблицу (64 кадра × 768 × int16). 128 гармоник —
  потолок формата (кадр 256 точек): ниже ~125 Гц верх обрезается раньше 16 кГц.
- Осц 2: семитоны ±24, detune (макрос DET). Hard sync: осц 2 сбрасывается фазой осц 1;
  в BL — с BLEP-коррекцией скачка, в WT — без (алиасинг допустим).
- Sub: BL-квадрат −1/−2 октавы от осц 1, свой уровень. Noise: белый шум, свой уровень.
- CPU: WT читает ~8 точек/осц/сэмпл из mmap flash; риск — промахи кэша при многих голосах на
  разных таблицах. Бенч `-DAUDIO_BENCH_SYNTH`; при блоке > 4 мс SYNTH идёт под лимит тяжёлых голосов
  (`kFmVoiceMax`) или получает свой.

## 2. Параметры, макросы, UI

Макросы — `Instrument::macro[5]`, с ними сразу работают fx DCY..CON, LFO-назначения Dec..Con и локи:

| fx  | макрос SYNTH                               |
|-----|--------------------------------------------|
| DCY | SHP1: POS (WT) / PW (Square) осц 1         |
| COL | SHP2: то же для осц 2                      |
| SHP | MIX: баланс осц 1 ↔ осц 2                  |
| SWP | DET: detune осц 2, ±50 центов              |
| CON | SENV: глубина env→SHAPE (±), оба осц        |

Колонка FX показывает общие имена; INST и список LFO-назначений — подписи SYNTH (как у DRUM).

Новые поля `Instrument`: режим и имя таблицы (`char[17]`) для осц 1/2; семитоны осц 2; sync;
sub (уровень, октава −1/−2); noise (уровень); env→SHAPE атака/спад (`envTimeMs`).

INST для SYNTH — 6 страниц: MAIN / ENV / OSC / MOD / FILT / LFO.
- OSC: режим + таблица осц 1 и 2 (тап по имени → браузер /wavetables), SHP1, SHP2, MIX, семитоны,
  DET, sync; превью текущего кадра WT (кадр под SHAPE, ~100 px).
- MOD: sub, noise, SENV, атака/спад env→SHAPE.
- Живое прослушивание, как у FM.

## 3. Таблицы: хранение, импорт, проект

- Вшитые: ~8 таблиц (Saw→Sqr, PWM-развёртка, Sine→Saw, Tri→Sqr, Formant, Harm-add, Sync-sweep,
  Bell), генерируются аддитивно скриптом при сборке, лежат в прошивке уже с мипмапами (≈ 770 КБ
  в app-разделе). Имена со звёздочкой (`*SAWSQR`), работают без SD и без импорта.
- Библиотека на SD: `/wavetables` (корень + подпапки, как /samples). Пользователь копирует туда
  свою коллекцию (661 таблица WaveEdit). Браузер — как импорт сэмплов, превью кадра 0. Wi-Fi видит
  `/wavetables`.
- Форматы импорта:
  - WaveEdit: mono 16 bit, длина кратна 256, ≤ 64 кадров (64 × 256 = 16384);
  - Serum/Vital: кадр 2048 (длина кратна 2048 или чанк `clm`), кадры прореживаются до 256 через
    FFT; кадров > 64 — берутся равномерно;
  - частота из заголовка игнорируется;
  - удаление DC в каждом кадре, нормализация пика таблицы.
- Мипмапы: на кадр одна FFT-256, затем обратные FFT с обрезкой гармоник на 8 уровней; при импорте,
  результат пишется в банк flash. Чистые функции в `lib/core`.
- Банк: запись WT (96 КБ) с флагом в `BankEntry` (`rate = 0` или отдельное поле — решить в плане),
  имя — `w` + crc32 исходных 16384 сэмплов (не пересекается с ключами сэмплов).
- Проект: отдельный список `Project.wavetables[32]` (имя, crc), чанк `WTBL`. Save пишет исходник
  в `/projects/NAME/<имя>.wav` (32 КБ); load подтягивает недостающие из папки проекта и пересчитывает
  мипмапы. Вытеснение общее с сэмплами (`bankMakeRoom`).
- Нет таблицы (ни в банке, ни в папке проекта) → осциллятор молчит, имя в INST красное.

## 4. Форматы, пресеты, тесты

- Чанк `SYNI`: запись на инструмент, `kSynRecSize = 48` (2 × 17 имени таблиц, режимы, семитоны,
  sync, sub, noise, атака/спад env→SHAPE, reserved). Чанк `WTBL` — список таблиц проекта.
  Старые файлы: чанков нет → дефолты. `Project` вырастает примерно на 32 × 21 Б + 16 × ~40 Б;
  лимит Wi-Fi-загрузки проекта (512 КБ) выдерживает.
- Пресеты `.mti` v3: + SYNTH-запись; v1/v2 читаются. Пресет хранит имя таблицы: если её нет
  в проекте — подтянуть из `/wavetables` или вшитых, иначе «отсутствует». Заводских ~10 (bass, acid,
  lead, pad, pluck, PWM-strings, sync-lead, wt-sweep, bell, sub-bass) — только на вшитых таблицах.
- Native-тесты:
  - BL: энергия алиасинга Saw/Square на высоких нотах ниже порога (против наивных); PW и sync без
    щелчков и NaN;
  - мипмапы: на уровне k нет гармоник выше 128>>k, нет DC, гладкий переход уровней;
  - импорт: WaveEdit, Serum 2048 + `clm`, > 64 кадров, битые WAV;
  - кодеки SYNI/WTBL/.mti v3 — roundtrip и старые файлы;
  - голос: макросы, env→SHAPE, отсутствующая таблица = тишина.
- Бенч `-DAUDIO_BENCH_SYNTH`: 16 голосов × 2 WT на разных таблицах + вариант на 8 голосов; CPU
  в статусбаре; по результату — решение о лимите голосов.
- На железе: CPU бенча, импорт из /wavetables, save/load с удалённой из банка таблицей,
  Wi-Fi /wavetables.

## Вне рамок v1

Unison/супер-пила, второй LFO и матрица модуляции, нарезка таблиц из сэмплов проекта, отдельные
fx WTP/PWM.

## Отклонения при реализации

- **Вшитые таблицы** не генерируются скриптом при сборке и не лежат в app-разделе: их спектры описаны
  в коде (`wt_builtin`), при старте (`audio::bankBegin`) недостающие строятся тем же `wtBuild` и пишутся
  в банк flash как записи `*ИМЯ` (≈ 770 КБ раздела `samples`, обычно один раз — при первом старте).
  Записи `*ИМЯ` никогда не вытесняются и не удаляются Clear cache. Итоговые имена: `*SAWSQR`, `*PWM`,
  `*SINSAW`, `*TRISQR`, `*FORMANT`, `*ORGAN`, `*SYNC`, `*BELL`.
- **Таблицы проекта** — в подпапке `/projects/NAME/wt/<имя>.wav` (а не рядом с сэмплами), чтобы имя
  таблицы не конфликтовало с именем сэмпла. Save пишет только таблицы, выбранные в инструментах
  (`projWtPrune`), Load подтягивает недостающие; отсутствующие входят в общий счёт «N SAMPLES MISSING».
- **Мипмапы:** вместо FFT — DFT только во float по таблицам синусов (`wt_mip`; double-тригонометрия на S3
  программная): 128 гармоник на кадр, импорт таблицы ~0,5–1 с на S3 при 240 МГц, отдельная FFT не нужна.
- **Импорт:** кадров < 64 — промежуточные кадры интерполируются по спектру, > 64 — берутся равномерно;
  нормализация пика таблицы (30000). Имя, занятое в проекте другой таблицей, получает суффикс `-2`, `-3`…;
  то же имя с теми же данными — используется имеющаяся запись.
- **Wi-Fi `/wavetables`:** лимит файла ~3 МБ (`kWtMaxBytes` = самая длинная таблица Serum 256 × 2048
  в стерео 24 бит + заголовки); папка проекта `wt` видна в разделе проектов («таблицы»).
- **Пресеты:** формат `.mti` v3 (запись SYNI), папка `/presets/SYNTH`; 10 заводских SYNTH-пресетов
  разложены по категориям BASS / LEAD / PAD / KEYS (BASS, ACID, SUBBASS; LEAD, SYNCLD; PAD, PWMSTR,
  WTSWEEP; PLUCK, BELL), только на вшитых таблицах. Таблица пресета, которой нет в проекте,
  импортируется из `/wavetables/<имя>.wav` (корень, при остановленном воспроизведении).
- **Локи макросов** (fx DCY..CON) на шагах без ноты действуют и на звучащие голоса SYNTH, как у FM / DRUM.
- **Лимит голосов (после бенча на железе 2026-10-06):** голос SYNTH с хотя бы одним WT-осциллятором — тяжёлый (`Voice::synHeavy`), в общем лимите 8 с FM / DRUM; BL-only SYNTH — лёгкий. WtOsc: уровень мипмапа считается раз в control-блок (`setLevel`), играется один уровень floor (без кроссфейда уровней — он без алиасинга с запасом в октаву), фаза 0.32 fixed point; SynVoice считает осцилляторы поблочно (всё per-sample принудительно инлайнится: вызовы на сэмпл на Xtensa дороже самого осциллятора); осциллятор вне микса не считается. Бенч на железе (`env:wt32-wtbench`, `/midi/bench.mid`): 8 голосов wt+wt 2927 → 1408 мкс на блок 4 мс, saw+saw 1770 → 928; flash / PSRAM / внутренняя RAM — одинаково (упор в вычисления, не в память). Было (P02 16 WT-голосов) 125 %, после оптимизации 70 % с пиками > 4 мс — отсюда лимит
  на железе.
- **UI:** таблица ищется при note-on (смена таблицы звучит со следующей ноты); Shape у SAW / TRI серый;
  осц. 2 в режиме TRI hard sync не принимает.
