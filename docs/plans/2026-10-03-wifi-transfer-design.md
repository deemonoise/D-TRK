# Передача файлов по Wi-Fi — дизайн

Статус: дизайн согласован 2026-10-03.

## Задача

Копировать файлы на microSD и с неё, не вынимая карту: заливать MIDI для импорта, скачивать и заливать проекты, удалять и переименовывать файлы. Обновлять прошивку по воздуху.

## Решения

- Домашний Wi-Fi (STA), адрес `http://tracker.local` (mDNS) или IP. Своей точки доступа нет.
- Работа через веб-страницу в браузере. WebDAV/FTP не делаем.
- SSID и пароль вводятся на экране и хранятся во flash (Preferences/NVS). Файла с паролем на карте нет.
- Wi-Fi включается только на отдельном экране режима передачи, при остановленном транспорте. На выходе Wi-Fi полностью выключается.

## Сценарий

1. Вкладка FILE → пункт **WI-FI**.
2. Нет карты — toast, режим не включается.
3. Есть несохранённые изменения — меню CANCEL / SAVE & CONTINUE (неактивно у `untitled`) / CONTINUE WITHOUT SAVING. Причина: после обновления прошивки устройство перезагрузится.
4. Транспорт останавливается (`storage::stopEngine()`), Play в режиме заблокирован.
5. Сеть не настроена — скан, выбор сети из списка, ввод пароля.
6. Экран WI-FI:
   - статус: «подключение…», адрес `http://tracker.local` и IP, или ошибка;
   - лог последних действий («↑ song.mid», «✕ old.mtp»);
   - кнопки EXIT и CHANGE NETWORK.
7. Выход:
   - Wi-Fi выключается;
   - файл открытого проекта изменён через веб — меню KEEP CURRENT / RELOAD FROM CARD;
   - файл удалён или переименован — toast, проект в памяти остаётся (можно сохранить).
8. Режим — диалог внутри вкладки FILE (как импорт MIDI). Уход с вкладки = выход из режима.

### Экранная клавиатура

Сейчас она рассчитана на имена: до 16 символов, `0-9 A-Z a-z - _`. Для пароля нужно:
- длина до 63 символов (максимум WPA2);
- страница символов (печатные ASCII `!`–`~`) и пробел;
- длина задаётся при открытии, режим имён остаётся как есть.

## Устройство

| Файл | Что |
|---|---|
| `src/net/wifi.cpp/.h` | STA, подключение с таймаутом 15 с, скан, mDNS `tracker`, NVS (SSID/пароль), полное выключение |
| `src/net/web.cpp/.h` | `WebServer` из Arduino-core, обработчики API, страница |
| `src/net/web_page.h` | HTML/CSS/JS одной строкой (PROGMEM), без внешних CDN |
| `src/ui/wifi_dialog.cpp/.h` | диалог режима во вкладке FILE, выбор сети, лог |
| `lib/core/src/file_rules.cpp/.h` | чистые правила: папки, имена, расширения, размеры, JSON-список |

- `WebServer::handleClient()` вызывается из `tick()` UI-задачи. Картой по-прежнему владеет одна задача, блокировки не нужны.
- Секвенсор в режиме остановлен, поэтому джиттер от Wi-Fi на ядре 0 не важен.
- Внешних библиотек нет: WiFi, ESPmDNS, WebServer, Preferences входят в Arduino-core.

## API

| Метод | Путь | Что |
|---|---|---|
| GET | `/` | страница |
| GET | `/api/list?dir=midi\|projects` | JSON `[{"name":"a.mid","size":123}, …]` |
| GET | `/api/file?dir=..&name=..` | скачать (`Content-Disposition: attachment`) |
| POST | `/api/upload?dir=..&overwrite=0\|1` | multipart; потоком в `.tmp`, проверка, rename |
| POST | `/api/rename?dir=..&from=..&to=..` | переименовать |
| POST | `/api/delete?dir=..&name=..` | удалить |
| POST | `/api/update` | multipart `.bin`; `Update` пишет в свободный OTA-слот, после ответа перезагрузка через 1 с |

Ответы на ошибки: HTTP 4xx/5xx и короткий текст, который страница показывает.

## Проверки

- Доступны только `/midi` и `/projects`. В имени запрещены `/`, `\` и `..`.
- `/projects`: расширения `.mtp` и `.bak`, базовое имя проходит `storage::validName`, лимит размера — максимум формата.
- `/midi`: только `.mid` (список на устройстве видит только его), имя до `kNameMax - 1` символов без расширения, печатные ASCII без `: * ? " < > |`, до 512 КБ (лимит импорта).
- Файл существует, а `overwrite=0` — ответ 409, страница спрашивает «заменить?».
- Залитый `.mtp` проверяется чтением во временный Project (CRC, версия). Битый удаляется, в ответе текст `storage::resultText`.
- При замене `.mtp` старый файл уходит в `.bak`, как при сохранении.
- Удаление или переименование открытого проекта разрешено. Экран режима показывает предупреждение.

## Обновление прошивки (OTA)

Разметка `default_16MB.csv` уже содержит `otadata`, `app0`, `app1`: новая прошивка пишется в свободный слот, при ошибке остаётся старая.

- Веб: секция «Прошивка», файл `firmware.bin` (`.pio/build/wt32/firmware.bin`). На экране трекера «FIRMWARE n KB».
- PlatformIO: в режиме Wi-Fi работает ArduinoOTA (он же ведёт mDNS `tracker`). Env `wt32-ota` (`upload_protocol = espota`, `upload_port = tracker.local`): `pio run -e wt32-ota -t upload`. На экране «FIRMWARE n%».
- Пароля нет, как и на файлах: прошить может любой в той же сети, пока режим открыт. Предупреждение в README.

## Ошибки

- Нет карты — режим не включается.
- Не подключились за 15 с — «NO NETWORK / WRONG PASSWORD», кнопка CHANGE NETWORK.
- Обрыв загрузки (`UPLOAD_FILE_ABORTED`) — `.tmp` удаляется.
- Карта заполнена — 507 и `.tmp` удаляется.
- Пароля на веб-странице нет: доступ есть у любого в той же сети, пока открыт режим. Осознанное упрощение, указать в README.
