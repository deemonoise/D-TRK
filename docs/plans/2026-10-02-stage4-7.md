## Этап 4: сохранение и загрузка (A)

### 4.1 Ядро: `lib/core/src/project_io.h/.cpp`

Формат `.mtp`, little-endian, чанковый:

```
"MTRK" u16 version=1 u16 reserved
chunk*: id[4] u32 size payload[size]
"CRC " u32 size=4 u32 crc32(всех байт файла до этого чанка)
```

Чанки (порядок при записи такой, при чтении — любой; неизвестные пропускаются):
- `PROJ`: name[17], u16 bpm, u8 scaleRoot, u8 scaleType, u8 songMode, u8 chainLen, u8 chain[64].
- `TRKS`: u8 count=8, затем на дорожку: name[9], channel, defVel, defGate, ccA, ccB, program, u8 flags (bit0 mute, bit1 solo).
- `PATN` (по одному на непустой паттерн): u8 index, u8 length, u8 res, u8 swing, затем 8 × length шагов по 6 байт (note, vel, fx0.cmd, fx0.val, fx1.cmd, fx1.val). Шаги за `length` не пишутся.

Пустой паттерн = `isEmpty()` и length/res/swing по умолчанию. Такие не пишутся и при чтении остаются `clear()`.

API — без файловой системы, через абстрактные потоки, чтобы тестировать на native:

```cpp
struct ByteSink { virtual bool write(const void* d, size_t n) = 0; };
struct ByteSource { virtual bool read(void* d, size_t n) = 0; virtual bool skip(size_t n) = 0; };
uint32_t crc32(const void* d, size_t n, uint32_t prev = 0);
bool saveProject(const Project& p, ByteSink& out);  // считает CRC по ходу
enum class LoadErr { Ok, BadMagic, BadVersion, Truncated, BadCrc, BadValue };
LoadErr loadProject(ByteSource& in, Project& out);  // out.reset() перед чтением
```

Правила загрузки:
- Значения валидируются и клампятся: length 4..128, res < Count, swing 50..75, channel 0..15, bpm 20..300, scaleRoot < 12, scaleType < Count, chainLen ≤ 64, индексы паттернов < 16, fx cmd < Count (иначе None).
- Неверная версия: major > 1 → `BadVersion`.
- CRC проверяется по всем байтам до чанка `CRC `. Отсутствие CRC = `Truncated`.

Тесты (`test/test_project_io`):
- round-trip полного проекта: все поля, несколько паттернов, длины 4 и 128, fx, chain, songMode;
- пустые паттерны не пишутся (размер файла мал);
- неизвестный чанк в середине пропускается (forward-compat);
- битый байт → `BadCrc`; обрезанный файл → `Truncated`; неверная магия → `BadMagic`;
- мусорные значения клампятся.

В `model.h` добавить `bool songMode = false;` в `Project` (используется в этапе 7), сбрасывать в `reset()`.

### 4.2 Железо: `src/hw/sdcard.h/.cpp`

### 4.3 Логика: `src/storage/storage.h/.cpp`

**Save(name):**
1. Снапшот проекта под `lockProject` (memcpy в PSRAM-буфер ~100 КБ).
2. `saveProject` в `/projects/name.tmp`.
3. Перечитать `.tmp` и проверить через `loadProject` во временный Project. Можно в тот же буфер снапшота, если он уже не нужен; иначе проверить только CRC потоковым чтением.
4. `name.mtp` → `name.bak` (старый `.bak` удалить), затем `.tmp` → `.mtp`.
5. Записать `/last.txt`.

Сохранение работает во время воспроизведения.

**Load(name):**
1. Прочитать в временный Project (PSRAM).
2. При ошибке CRC: если есть `.bak`, предложить загрузить его.
3. Если ок: `engine::post(Stop)`, дождаться `!status.playing`, под lock скопировать, `post(SetBpm)`.
4. Записать `/last.txt`, очистить undo.

**New:** стоп, `reset()`, имя `untitled`.

**Автозагрузка:** при старте, если SD есть и есть `/last.txt`, загрузить. Иначе demo-паттерн, как сейчас.

**Флаг несохранённых изменений:** в `App` счётчик правок `editSeq_` (инкремент в `pushUndo`, в `ParamList` edit, в BANK-операциях; проще — в каждом месте, где берётся `lockProject` для записи из UI). Значение `savedSeq_` запоминается после save/load/new. `*` в статус-баре после имени паттерна, если не равны.

### 4.4 UI: вкладка FILE (`src/ui/file_screen.*`) + экранная клавиатура (`src/ui/keyboard.*`)

- Список действий: `Save`, `Save As…`, `Load…`, `New`, `Import MIDI…` (этап 6: пока неактивен).

- `Load`: список `/projects/*.mtp` (ParamList-подобный скролл, drag), тап — загрузить. При несохранённых правках сначала меню-подтверждение `Discard changes?`.
- `New`: подтверждение при несохранённых правках.
- Ошибки и успех — toast.
- FILE-вкладка становится активной. Индикатор SHIFT на её месте остаётся как сейчас.

## Этап 5: Euclid

### 5.1 Ядро (B): `lib/core/src/euclid.h/.cpp`

```cpp
// Bjorklund: hits ≤ steps ≤ 128. out[i] = true для удара. rotation сдвигает вправо.
void euclid(int hits, int steps, int rotation, bool* out);

enum class EuclidFill : uint8_t { Root, Up, Down, UpDown, Random, Count };
struct EuclidParams {
  uint8_t hits = 4, length = 16;  // length ≤ длины паттерна, повторяется по паттерну
  int8_t rotation = 0;
  EuclidFill fill = EuclidFill::Root;
  uint8_t baseNote = 36;  // база для заполнения
  uint8_t range = 1;      // октав (1..4) для Up/Down/UpDown/Random
  uint8_t vel = 100;
  uint8_t accentVel = 127;
  uint8_t accentEvery = 0;  // 0 = нет акцента; N — каждый N-й удар
  uint32_t seed = 1;
  bool merge = false;       // true: писать только в пустые шаги; false: заменить дорожку (в пределах длины паттерна)
};
// Пишет дорожку track паттерна p; ноты — в ладу root/scale.
void applyEuclid(Pattern& p, int track, const EuclidParams& e, uint8_t root, ScaleType scale);
```

Правила:
- Up/Down/UpDown идут по ступеням лада от `baseNote` в пределах `range` октав и заворачиваются.
- Random — `Rng(seed)`, ступень в диапазоне.
- Root — всегда `baseNote`, привязанная к ладу (ближайшая нижняя нота лада).
- В режиме Replace шаги без удара очищаются, fx удаляются.

Тесты: эталоны E(3,8) = `x..x..x.`, E(5,8) = `x.xx.xx.`, E(2,5), E(4,16), E(0,n), E(n,n); rotation; повтор length 5 на паттерне 16; merge не трогает занятые шаги; Up в C major от 60: 60, 62, 64…; Random детерминирован от seed; accent.

### 5.2 UI (C): диалог Euclid

- Пункт `Euclid…` в контекстном меню GRID (без выделения). Если пунктов больше 12, меню скроллится — это поддерживается.
- Экран-диалог поверх GRID (ParamList): Hits, Length, Rotation, Fill, Base note (имя ноты), Range, Velocity, Accent every, Accent vel, Seed (`Shift+клик` или пункт `Reseed`), Mode Replace/Merge. Внизу `OK` / `Cancel`.
- **Превью:** при открытии `pushUndo()`, сохраняется копия дорожки. Каждое изменение параметра переписывает дорожку из копии и применяет Euclid под lock, так что звучит сразу. `Cancel` восстанавливает копию, `OK` оставляет (undo уже записан). Копия дорожки — 128 шагов × 6 байт.
- Параметры Euclid запоминаются на дорожку в RAM между открытиями (не сохраняются в файл).

## Этап 6: импорт MIDI

### 6.1 Ядро (B): `lib/core/src/smf.h/.cpp` и `lib/core/src/midi_import.h/.cpp`

Парсер SMF:

```cpp
struct SmfNote { uint32_t tick, len; uint8_t note, vel, src; };  // src = индекс источника
struct SmfSource { uint8_t track, channel; char name[17]; uint16_t count; uint8_t lo, hi; };
struct SmfInfo {
  uint16_t ppq; uint32_t firstTempoUsPerQ;  // 500000 по умолчанию
  uint8_t sourceCount; SmfSource src[32];
  uint32_t noteCount; uint32_t lastTick;
};
enum class SmfErr { Ok, NotMidi, Smpte, Truncated, TooManyNotes, Unsupported };
// notes — буфер вызывающего (PSRAM), cap элементов.
SmfErr parseSmf(const uint8_t* data, size_t size, SmfInfo& info, SmfNote* notes, uint32_t cap);
```

- Формат 0 и 1 (формат 2 → `Unsupported`), running status, VLQ, meta: 0x03 track name, 0x51 tempo (первый); sysex пропускается.
- NoteOn с vel 0 = NoteOff. Незакрытые ноты закрываются концом трека.
- Источник = (track, channel). Больше 32 — лишние отбрасываются.
- Ноты отсортированы по tick.

Маппинг:

```cpp
enum class MonoMode : uint8_t { Highest, Lowest, First };
struct ImportMap {
  int8_t target[32];         // источник → дорожка 0..7 или -1
  int8_t transpose[32];      // ±24
  uint16_t offsetBars = 0;   // пропустить N тактов (4/4)
  Resolution quant = Resolution::Sixteenth;
  uint8_t patternLen = 16;   // длина создаваемых паттернов
  uint8_t firstPattern = 0;  // от какого паттерна писать
  MonoMode mono = MonoMode::Highest;
  bool useSourceChannel = false;  // CHN fx, если канал источника ≠ каналу дорожки
  bool useTempo = true;
  bool keepMicrotiming = false;   // отклонение от сетки → NDG
};
struct ImportResult { uint8_t patternsWritten; uint16_t bpm; uint32_t notesDropped; };
ImportResult importSmf(const SmfInfo& info, const SmfNote* notes, uint32_t n,
                       const ImportMap& m, Project& p);
```

- Квантование к ближайшему шагу.
- Длина шага в тиках файла = `ppq * ticksPerStep(quant) / 96`, без промежуточного округления (считать в 64-битных дробях): например, 1/16 = ppq/4, 1/8T = ppq/3. Шаг ноты = round((tick − offsetBars·4·ppq) / stepTicks).
- Материал режется на паттерны по `patternLen`, подряд от `firstPattern` до P16. Остаток → `notesDropped`.
- Паттерны, которые пишутся, сначала очищаются (только дорожки-цели), получают `length = patternLen` и `res = quant`.
- Моно-редукция для нескольких нот в одном шаге одной дорожки.
- Длительность → `GAT` (в кодировке gatePercent, ближайшее), если отличается от `defGate` дорожки больше чем на 10 %. Микротайминг → `NDG` (−50..+50 % шага). Обе fx — в свободные слоты.
- `useTempo`: bpm = 60e6 / tempo, кламп 20..300.

Тесты: собрать в тесте байты SMF вручную:
- формат 0 с running status;
- формат 1 с двумя треками и именами;
- vel 0 как off;
- темп;
- SMPTE → ошибка;
- обрезанный → `Truncated`;
- импорт: квантование, моно Highest/Lowest/First, transpose, offset, резка на 2 паттерна, GAT, NDG, CHN, лимит P16.

### 6.2 UI (D): импорт

- `FILE → Import MIDI…` → список `/midi/*.mid`. Файл больше 512 КБ → ошибка.
- Чтение в PSRAM, буфер нот 16384 × 12 байт.
- Экран маппинга (ParamList):
  - на каждый источник строка `TRK name ch N (count, lo–hi) → T1..T8/skip`, плюс transpose;
  - глобальные: Offset bars, Quantize, Pattern length, First pattern, Mono, Source channel, Use tempo, Microtiming;
  - `IMPORT` / `CANCEL`.
- Перед импортом: подтверждение, `post(Stop)`, затем импорт под lock (или в копию с последующим memcpy под lock).
- Undo очищается. Toast «Imported N patterns».
- Буферы освобождаются после выхода.

## Этап 7: song mode (E)

- `Project.songMode` и `chain[64]`/`chainLen` уже в модели и формате.
- **Секвенсор:** при `songMode && chainLen > 0`:
  - старт с `chain[0]`;
  - в конце прохода переход на следующий элемент chain, после последнего — на первый (loop);
  - ручная очередь паттерна (`queuePattern`) в song mode игнорируется.
  - `Status` публикует позицию в chain (`songPos`, −1 вне song mode).
  - TDD в `test_sequencer`: переходы, loop, rewind/tempo change через границу элемента chain, pause/resume, stop.
- **UI:** вкладка BANK получает переключатель `SONG` (в заголовке или меню).
  - В song mode экран BANK показывает список chain вместо плиток: строки `01 P03`; энкодер или тап выбирает строку, поворот в правке меняет паттерн.
  - Меню строки: Insert, Delete, Duplicate.
  - Добавление: тап по плитке в режиме Append; кнопка `+`.
  - Статус-бар в song mode: `S03 P05`.
- Все изменения chain — под lock, с флагом несохранённых правок.
