# Сцены и кроссфейдер (SCENE / морф A↔B) — дизайн

Идея как у кроссфейдера Octatrack: сцена — набор «замков» параметров микса и звука; две сцены стоят
на концах фейдера A и B, фейдер плавно переводит звук из одной в другую вживую. Опирается на:
- TrackCfg (vol, pan, insert: drive / driveModel / crushBits / crushRate, gateDepth, modSend) и
  SynthModel (master, DLY / RVB / MOD / MSTR) из `lib/core/src/model.h`;
- зеркало модели ESP → Teensy (`StateMirror`, чанки `synth_model.h`, `audio_link.cpp`,
  `link_server.cpp::onStateSet`);
- порядок «база → p-lock → LFO / follower» в `Synth::control` (`synth.cpp`, блок «The strip's values»).

Термин: в старом формате файла «scene» — маски mute (чанк `SCNS`, legacy). Новый чанк называется
`SCEN`, в UI слово «SCENE» / «СЦЕНА» до сих пор не занято.

## Цель

- 8 сцен на проект. Сцена хранит только заданные параметры (замки), остальные «не заданы».
- Фейдер 0..127: 0 — целиком сцена A, 127 — целиком сцена B. Параметр, не заданный в сцене,
  берёт на её конце текущее (базовое) значение проекта.
- Морф идёт на синт-плате по блокам, со сглаживанием; по линку едет одна позиция фейдера.
- Базовые значения проекта фейдер не трогает: сохранение, undo, экраны правят базу как раньше.

Не делаем (YAGNI): сцены для MIDI-дорожек (CC), mute / solo в сцене, режимы эффектов (Dly mode,
Rvb mode, Mod type, Shim int) и параметры движков инструментов (макросы, ADSR, LFO), сцены на
паттерн, больше двух концов (морф по кругу).

## Где живут сцены

**Проект**, не паттерн: всё, что сцена меняет (TrackCfg, master), — данные проекта; сцена на
паттерн дублировала бы их 16 раз и рвала бы морф на смене паттерна. 8 сцен — по числу кнопок
дорожек (выбор сцены кнопкой N в правке сцен) и PERF.

```cpp
// lib/core/src/scene.h
constexpr int kScenes = 8;
enum ScnTrk : uint8_t {   // параметры дорожки, порядок = биты маски, хранится в файле: новые в конец
  kScnVol, kScnPan, kScnDrv, kScnDty, kScnBit, kScnSrr, kScnGte, kScnDly, kScnRvb, kScnMod,
  kScnCut, kScnRes, kScnTrk };                       // 12 <= 16
enum ScnMst : uint8_t {   // параметры мастера
  kScnMain, kScnDTime, kScnDFb, kScnDTone, kScnDChar, kScnDLvl, kScnRSize, kScnRDamp, kScnRLvl,
  kScnMRate, kScnMDepth, kScnMLvl, kScnEqLo, kScnEqHi, kScnMst };   // 14 <= 16
struct Scene {
  uint16_t trkMask[kTracks];          // бит p: параметр p дорожки задан
  uint8_t trk[kTracks][kScnTrk];
  uint16_t mstMask;
  uint8_t mst[kScnMst];
};                                    // 240 Б
```

- `Project`: `Scene scenes[kScenes]`, `uint8_t sceneA = 0, sceneB = 1` (индексы концов), всё ~1,9 КБ.
- `SynthModel` (зеркало на Teensy): `uint8_t xfade` в группе master (после `shimInt`) и в самом
  конце структуры `Scene sceneLive[2]` — копии сцен A и B. На Teensy едут только два конца, не все
  восемь: +481 Б в RAM1 Teensy (модель — глобальная в DTCM) и столько же в тени `StateMirror` на ESP.
- Одна функция `syncSceneLive(Project&)` копирует `scenes[sceneA / sceneB]` в `sceneLive`; её зовут
  после любой правки сцены, смены A / B и после загрузки проекта.

## Параметры сцены

Дорожка (только INT; у MIDI-дорожки в правке сцены строки серые):

| Код | Поле | Тип |
|---|---|---|
| VOL | `TrackCfg::vol` 0..127 | непрерывный |
| PAN | `TrackCfg::pan` 0..127 | непрерывный |
| DRV, BIT, SRR | `drive`, `crushBits`, `crushRate` | непрерывный (0 = выкл.) |
| DTY | `driveModel` (TNH CLP FLD RCT ASY) | дискретный |
| GTE | `gateDepth` | непрерывный |
| DLY, RVB | посылы инструмента дорожки (`Instrument::send / rsend`) | непрерывный |
| MOD | `modSend` | непрерывный |
| CUT, RES | `Instrument::cutoff / reso` инструмента дорожки | непрерывный |

DLY / RVB / CUT / RES физически принадлежат инструменту, но сцена хранит их **по дорожке** и
подменяет только для голосов этой дорожки (как p-lock FLT / DLY: `v.track`). Две дорожки на одном
инструменте морфятся независимо; KIT-дорожка — посылы и фильтр KIT, как сейчас.

Мастер: MAIN (`masterVol` 0..200), DLY time (дискретный, 1..16 шестнадцатых), DLY fb / tone /
char / level, RVB size / damp / level, MOD rate / depth / level, EQ low / high.

## Правило морфа

Для параметра с базой `b`, позиция `x = xfade / 127`:

```
a = A задан ? A.val : b
c = B задан ? B.val : b
непрерывный: v = round(a + (c - a) * x)
дискретный:  v = xfade < 64 ? a : c
```

- Не задан ни в A, ни в B → ровно `b` (бит в бит, без округления): проект без сцен звучит как
  сейчас.
- Задан только в A → на конце B возвращается к базе: «замок держит только то, что задано».
- Значения сырые 0..127 (VOL — в своих единицах fader-а, без пересчёта в дБ), как у Octatrack.
- Общая функция в `lib/core` (`sceneValue(base, A, B, param, xfade)`) — одна и та же на ESP
  (показ на MIX) и на Teensy (звук).

## Синт-плата: где применяется

- `Synth` держит `MorphView`: `trk[16][12]`, `mst[14]` (эффективные байты) и `xf` (сглаженная
  позиция). Пересчёт раз в блок, только если что-то изменилось: целевой `xfade` ≠ `xf`, или пришёл
  чанк Master / Tracks / Scenes / Instr (счётчик поколений в `onStateSet`). Цена: 16×12 + 14
  лерпов на блок при движении фейдера, иначе ноль.
- Сглаживание: `xf` идёт к `xfade` со скоростью полного хода за ~30 мс (линейно в блоках): шаги
  энкодера и редкие кадры линка не дают ступенек.
- Места чтения: `trackVol`, `trackPan`, `insertCfg` (drive, crush, model, gate depth, modSend),
  `send / rsend` и `cutoff / reso` в `control` / `controlFilter`, мастер (`dlyFb`, `rvbSize`, …)
  в своих стадиях — все через `MorphView` вместо прямого `p_.…`. Если `sceneLive` пусты
  (обе маски 0), `MorphView` возвращает базу без копирования.

## Приоритеты: p-lock, LFO, follower, PERF

Порядок для каждого параметра голоса / дорожки:

1. база проекта;
2. **морф сцены** заменяет базу;
3. **p-lock** шага (FLT, RES, DLY, RVB, DRV, BIT, SRR, PAN, DTY, GTE, MOD) заменяет результат —
   замок шага сильнее фейдера, как сейчас он сильнее базы;
4. **LFO и follower** прибавляются сверху (они модулируют «вокруг» значения, теперь
   морфированного).

PERF стоит после мастера и не меняется; фейдер на него не действует. Это минимальная правка кода:
морф просто становится новой «базой» в существующем `lock ? lock : base`.

## Линк: что едет и как часто

- Позиция фейдера — байт `xfade` в чанке Master (~40 Б). Новый тип кадра не нужен: `StateMirror`
  шлёт грязный чанк, один в полёте, ждёт Ack. Пока чанк в пути, новые движения копятся в
  проекте, уходит последнее значение — **естественное ограничение частоты** (≤ 1 чанк на RTT,
  ~1–2 мс на 3 Мбод). Дополнительно UI не пишет `xfade` чаще раза в 10 мс (дрэг по экрану).
- Правка сцены или смена A / B — чанк `Scenes` (`sceneLive`, 480 Б, ~1,7 мс). Не в реальном
  времени, но и не при каждом движении.
- Новый чанк `Chunk::Scenes = 4`, `kChunks` 4 + 32 → 5 + 32, `sizeof(SynthModel)` растёт:
  **kProtocol +1**, проверка `Hello::modelSize` ловит несовпадение прошивок.
- Перезагрузка синт-платы: `mirror.invalidate()` пересылает всё, позиция фейдера восстановится сама.
- Render WAV / Resample идут по той же модели: рендер звучит при текущей позиции фейдера (статично).

## UI

**MIX: полоса кроссфейдера** между полосами и осциллографом (высота ~16 px): `A3 ━━━●━━━ B5`.
- Тап / дрэг по полосе — позиция; тап по полосе выбирает её (подсветка, как выбор панорамы), и
  энкодер (и A + поворот, <kbd>Shift</kbd> ×8) крутит фейдер вместо MAIN. Снимается так же, как выбор
  панорамы (тап <kbd>B</kbd>, повторный тап, уход с вкладки).
- Тап по `A3` / `B5` — выбрать сцену этого конца: поворот энкодера листает 1..8.
- Полосы показывают эффективное значение (VOL / PAN) тонкой риской поверх заливки базы, когда
  фейдер что-то двигает; у параметра под замком сцены — жёлтая метка.

**PERF (GRID и SONG):** пока PERF включён и ни один эффект не зажат, **A + поворот** двигает
кроссфейдер (сейчас A + поворот в PERF уходит в правку ячейки — она и так выключена режимом).
Toast `XFADE 64 A3>B5`, в шапке рядом с бейджем PERF — `X64`.

**Правка сцен — вид SCENE на MIX** (пункт меню / долгий тап по `A3`/`B5`): та же раскладка из 8
полос + MAIN, но полоса показывает **один параметр** сцены для 8 дорожек:
- шапка `SCN 3  < VOL >` — тап по имени параметра или Shift + поворот листают VOL .. RES;
  полоса MAIN показывает выбранный параметр мастера (тап по её имени листает MAIN .. EQ HI);
- незаданный параметр — пустая рамка и `---`; первая правка (дрэг, держать кнопку дорожки +
  поворот, как громкость сейчас) задаёт его, начиная с текущей базы; <kbd>Shift</kbd> + тап по
  полосе — снять замок;
- кнопка дорожки N в этом виде без поворота — выбрать сцену N для правки;
- пока открыт вид SCENE, фейдер прыгает на конец редактируемой сцены (если она A или B), чтобы
  было слышно, что правится; при выходе возвращается.

Меню вида SCENE: **Capture mix** (VOL + PAN всех INT-дорожек из текущей базы в сцену),
**Copy scene → N**, **Clear scene**. Больше захватов нет: «сцена хранит только заданное».

Шаговый fx `XFD` в первой версии **не делаем** (см. вопросы).

## Сохранение

Новый чанк `SCEN` (проект, версия файла не меняется — старые читатели пропускают неизвестный
чанк):

```
u8 count (8), u8 trkParams (12), u8 mstParams (14), u8 sceneA, u8 sceneB, u8 xfade,
затем count записей: 16 x (u16 mask + trkParams байт), u16 mstMask + mstParams байт
```

- Читатель берёт известное: больше параметров в файле — лишние пропускаются, меньше — недостающие
  «не заданы»; биты маски выше известных отбрасываются. Значения клампятся (DTY ≥ Count → TNH,
  DLY time в 1..16, MAIN ≤ 200).
- Файл без `SCEN`: сцены пусты, A = 1, B = 2, фейдер 0 — звучит как раньше.
- Позиция фейдера сохраняется: проект открывается так, как его оставили.
- Пресеты инструментов сцен не касаются.

## Риски

- **Протокол и размер модели** — параллельные фичи тоже меняют `SynthModel` / `kProtocol`;
  при слиянии номер протокола и порядок полей согласовать.
- **RAM1 Teensy**: +~0,5 КБ модели и `MorphView` ~0,2 КБ; проверка RAM1-гейтом.
- **Артефакты** при морфе параметров, которые сейчас меняют редко: размер reverb (длины линий),
  время delay (дискретно, прыжок), crush. Если слышно — исключить из сцены или ввести сглаживание
  в самой стадии, но не усложнять морф.
- **Путаница базы**: правка базы параметра, который обе сцены держат, ничего не меняет на слух —
  отсюда жёлтая метка «под сценой» на MIX / TRACK / INST.
- Посылы и фильтр по дорожке, а не по инструменту: на экране INST видна база инструмента, а звучит
  морф — та же метка.
- Ручное слежение `syncSceneLive`: забытый вызов = Teensy играет старую сцену; поэтому одна функция
  и тест, что после каждой операции сцены `sceneLive` совпадает с `scenes[A / B]`.

## Решения (2026-10-15)

Дизайн принят со всеми рекомендациями; открытые вопросы закрыты так:

1. **p-lock шага сильнее сцены**: морф становится новой «базой» в `lock ? lock : base`, LFO и
   follower прибавляются сверху.
2. **Шагового fx `XFD` в v1 нет.**
3. **8 сцен** на проект.
4. **Набор параметров — таблица выше** (12 дорожки, 14 мастера); comp / SC depth, shimmer, mod fb
   не входят.
5. **Кроссфейдер в PERF — A + поворот** (пока PERF включён и ни один эффект не зажат), Shift ×8.
6. **Позиция фейдера сохраняется** в проекте (байт `xfade` в чанке `SCEN`).

Уточнения реализации (решено без вопросов):

- `Scene`, `ScnTrk`, `ScnMst`, `kScenes` живут в `model.h` (их держит `SynthModel`, `scene.h` зависел
  бы от `model.h` по кругу); функции — в `lib/core/src/scene.h/.cpp`.
- Номер чанка: `Chunk::Tuning = 4` уже занят микротюнингом, поэтому `Chunk::Scenes = 5`,
  `kChunks = 6 + kInstruments`, `kProtocol = 9`. `sceneLive[2]` стоит **после** `tuning` (конец
  модели), чанк Scenes = 480 Б — один кусок `StateSet`. Порядок отправки: Master, Tracks, Tuning,
  Scenes, инструменты, Samples, Wavetables.
- `MorphView` с кэшем заменён морфом **на чтении**: каждое место чтения зовёт инлайн
  `morphT(track, param, base)` / `morphM(param, base)`. Если параметр не задан ни в A, ни в B — это
  проверка двух масок и база без изменений (бит в бит). Кэш и счётчик поколений не нужны: синт
  самодостаточен (правки модели из тестов, офлайн-рендера и линка видны сразу), код меньше (ITCM).
  Голосовые параметры и полосы и так пересчитываются раз в control-период (32 сэмпла), мастер —
  раз в блок.
- Сглаживание: `xf_` идёт к `xfade` линейно раз в control-период, полный ход 0 → 127 за ~30 мс.
  Первый блок после создания синта и после `reset` ставит `xf_` сразу на цель (загрузка проекта с
  фейдером на B не «проезжает» от A).
- Дискретные параметры (DTY, DLY time) переключаются по сглаженной позиции: `xf >= 64` → B.
- Превью-дорожка (нота из GRID / INST вне дорожек) не морфится — звучит база.
- Посылы DLY / RVB не-KIT дорожки берут базу из инструмента голоса (как раньше), морф — по дорожке.
- Вид SCENE открывается **долгим тапом по полосе кроссфейдера** (или по `A3` / `B5`), закрывается
  тем же, <kbd>B</kbd> или уходом с вкладки. Меню вида — кнопки в строке кроссфейдера: `CAP`
  (Capture mix), `CLR` (Clear scene), `CPY` (Copy: затем кнопка дорожки N — копия в сцену N).
- В виде SCENE: поворот — значение параметра у дорожки курсора, A + поворот — значение
  выбранного параметра мастера, Shift + поворот — следующий / предыдущий параметр дорожки; тап по
  имени полосы — курсор на дорожку; тап по `MAIN` — следующий параметр мастера; держать кнопку
  дорожки + поворот — значение этой дорожки; кнопка дорожки без поворота — сцена N для правки.
- Пока открыт вид SCENE, фейдер стоит на конце правимой сцены (если она A или B); при выходе
  возвращается прежняя позиция. Сохранение проекта в это время запишет «прыгнувшую» позицию —
  мелочь, принято.
- Жёлтая метка «под сценой» в v1 только на MIX (риска эффективного VOL / PAN и жёлтое имя полосы);
  на TRACK / INST её нет.
- Заголовок `SCEN` получил байт числа дорожек: `u8 count, u8 tracks, u8 trkParams, u8 mstParams, u8 sceneA,
  u8 sceneB, u8 xfade`, затем `count` записей по `tracks` × (u16 mask + trkParams) + u16 mstMask + mstParams
  (сейчас 8 × 240 Б). Чанк пишется, только если хоть одна сцена не пуста или A / B / фейдер не по умолчанию.
- Курсор вида SCENE — кнопка дорожки срабатывает по отпусканию (держать + крутить правит значение, не
  меняя сцену).

### Стоимость на Teensy (замер 2026-10-15)

- `teensy41` (в скобках — база после Scala, до сцен): RAM1 variables 222848 (222816), code 248464 (247056),
  padding 13680 (15088), free for local variables 39296 (39328); ITCM code + padding = 262144 = 256 КБ —
  ворота пройдены, free ≥ 24 КБ. FLASH code 316392.
- `teensy41-bench`: RAM1 variables 224160, code 250992, padding 11152, free 37984 (ITCM 256 КБ).
- `wt32`: RAM 128676, Flash 1528939.
- ITCM +1,4 КБ: инлайн-проверка масок в местах чтения + два маленьких `MT_HOT` (`morphTrk`, `morphMst`);
  первый вариант с полным инлайном `sceneMix` давал +3,3 КБ. `scene.cpp` (имена, диапазоны, файл) — во
  flash через линкер-скрипт (на Teensy не линкуется: синт им не пользуется).
